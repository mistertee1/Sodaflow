# تشغيل المجانية ومحاسبة V2

الإصدار الحالي يوقف الاشتراك وحصص الباقات والسوبر أدمن عبر سياسة الإصدار. لا تغيّر سجلات الاشتراك القديمة لإزالة الحد، ولا تستعمل billing:migrate أو bootstrap لهذا النشر. كل بيانات العمل تظل في Firebase؛ لا ملف محلي بديل عند تعذر الحفظ.

## نشر الكود والقواعد

- مصدر التغيير PR147 إلى main، والدمج بيد المستخدم. نشر Rules وحده لا يثبت أن الواجهة والخادم الجديدين نُشرا.
- workflow «Deploy Firebase rules» ينفذ قبولاً كاملاً على المصدر المختار، ثم يقرأ اعتماد FIREBASE_SERVICE_ACCOUNT_JSON الموجود في GitHub Actions secret. لا تضع قيمته في commit أو issue أو المحادثة.
- يراجع الاتصال بالمشروع الأصلي sodaflow/default قراءة فقط، وينشر firestore.rules والفهارس المصدرية، ثم يشغّل accounting:rules:verify لإثبات SHA256 من Firebase. ليس فيه ترحيل باقات أو claims أو إنشاء قاعدة بديلة أو تفعيل شركات قائمة.
- إذا كانت النتيجة Missing repository secret أو IAM أو readiness، أصلح الاعتماد في إعداد GitHub الآمن ثم أعد workflow يدوياً من المصدر المراجع. لا إعادة إرسال كلمة مرور حساب التطبيق ولا فتح Rules للعامة.

## بدء المحاسبة

الشركة الجديدة من API الإصدار تبدأ V2 مع دليل حسابات وأرصدة صفرية، بعد إثبات قواعد هذا الإصدار.

الشركة المستخدمة تحتفظ بتكلفتها وتاريخها. من المخزون، سجل تكلفة كل منتج متتبع من وثيقة شراء فعلية وسعر صرفها اليدوي، مع السبب والمرجع. راجع المطابقة ثم استخدم «تفعيل المحاسبة V2 بعد المطابقة». لا تستنتج التكلفة من سعر البيع ولا تسجل صفراً لإخفاء تكلفة ناقصة.

إذا ظهرت رسالة نقص مصدر أو اختلاف org_id، راجع بيانات الشركة ومصدرها بدل إلغاء حماية العزل. لا تُكتب معاملات مالية حقيقية لمجرد الاختبار.

## حدود هذا التسليم

إتاحة V2 وإصلاح الباقات لا تعني اكتمال كل خطة المحاسبة والترحيل التراثي. تظل المراحل غير المقبولة في checkpoint الأصلي منفصلة. التشغيل الدوري للتصدير وIAM الخاص للملفات لم يفعّلا بهذا الطلب.
