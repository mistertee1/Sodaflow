# Excel4.2b.2b.1 — صلاحيات التصدير الحية

الأساس PR143 بعد قبول إدارة الجداول على b04e65ff، ونقطة التقدم 4c2c65c8. تمت قراءة main41df1632 والفروع وPRs أولاً؛ جميع تغييرات main المصدرية موجودة في السلسلة الحالية، فلا حاجة إلى نسخ ملفات المخزون أو Super Admin أو المزامنة فوقها.

## المشكلة والنتيجة المطلوبة

كان عامل الملف المحاسبي يمر عبر snapshot قابل للقراءة التاريخية بعد انتهاء الاشتراك، وقد يحصل على مجموعات مالية مرشحة فارغة ثم يعلن ملفاً ناجحاً. كما كان يبني هوية منشئ المهمة ببريد مؤكد مفترض، ولا يثبت حالة Auth الفعلية عند البناء والنشر والتنزيل.

1. اشتقاق هوية الخادم من Admin Auth getUser، وإثبات Rules، دون أعلام ثقة من الطلب.
2. قراءة العضوية والدور الفعلي والمؤسسة وV2 والاشتراك والميزات مع المصدر في المعاملة نفسها؛ انتهاء الحق يرفض التصدير قبل قراءة المصدر المحمي.
3. إعادة التحقق داخل معاملة إعلان الملف بعد الرفع الخاص. تغير نطاق المهمة أو إلغاء الحق/السياسة يمنع الإعلان ويحذف الملف غير المعلن.
4. التحقق الحي من المنشئ والمنزّل قبل توقيع رابط لا يتجاوز خمس دقائق أو انتهاء الاحتفاظ. تطابق المؤسسة والمهمة والمسار وبيانات الدليل شرط مستقل.
5. احترام إصدار سياسة مرتبطة ومالكها ونوعها وتوقيتها ومدة احتفاظها، مع بقاء execution_enabled:false حتى مرحلة claim والواجهة.

## القبول

اختبارات وحدة/API تحاكي سحب الدور/العضوية/Auth/الاشتراك/الميزة قبل البناء، وأثناء الرفع، وقبل التنزيل؛ وتحفظ الأرقام المالية الأصلية. اختبار HTTP حقيقي داخل العملية يثبت no-store وعدم تسريب رابط عند المنع. اختبارات Firestore demo-sudaflow:8091 تثبت المعاملة النهائية وعدم كتابة دليل اكتمال/انتهاء عند السحب، ومنع SDK للمهمة والفهرس. جميع الاختبارات القائمة وtypes/core/build ضمن check، ثم CI مع Java21 وواجهة regression كاملة.

## حدود المرحلة

لا due claim أو timer أو واجهة جدولة جديدة. لا تشغيل حقيقي لعامل إنتاجي أو تعديل IAM/Storage/Rules/Auth/claims أو بيانات مالية إنتاجية. بديل التخزين في الاختبارات ذاكرة اصطناعية؛ خصوصية الحاوية الفعلية تحتاج قبولاً مستقلاً. الرابط الموقع الصادر قبل سحب الحق يظل صالحاً حتى انتهاء مدته القصيرة. يظل تنسيق المحاسب القائم Excel XML .xls وحزمة المراجع XLSX والشركة JSON؛ تحويل التنسيقات ليس ضمن هذا الإصلاح. الدمج للمستخدم فقط، وPR تابع لـ143.
