# تقرير D3.2 — واجهة الميزانيات والتنبؤ النقدي

## النتيجة

أُنجزت D3.2 في PR #71، متراكبة على D3.1/PR #65. أصبحت إدارة الميزانيات، تقرير Budget vs Actual، وبنود التخطيط النقدي متاحة من واجهة عربية متجاوبة، مع تنبؤ نقدي مصدره أرصدة دفتر الأستاذ ومستحقات العملاء والموردين المتحقق منها في الخادم.

## المنفذ

- واجهة RTL/mobile لإنشاء الميزانيات وتعديلها، مع بنود SDG وUSD وأبعاد اختيارية للفرع ومركز التكلفة والمشروع.
- عرض Budget vs Actual من القيود الفعلية، مع الانحراف لكل حساب وإجماليات مستقلة لكل عملة.
- سجل محمي لبنود التنبؤ النقدي: مصروف متكرر أو دفعة مجدولة، لمرة واحدة أو أسبوعياً أو شهرياً.
- Cash Forecast يومي يضم رصيد النقدية الافتتاحي من دفتر الأستاذ، مستحقات العملاء والموردين، والبنود المجدولة؛ وينقل المتأخر إلى تاريخ `as_of` بدلاً من إسقاطه.
- توثيق مصدر تاريخ الاستحقاق، وعدّ السجلات الناقصة، وشرح صريح أن التنبؤ النقدي لا يساوي صافي الربح.
- تحقق خادمي من كل فاتورة بيع وشراء قبل إدخالها في التنبؤ، ورفض التقرير عند عدم تطابق السجل مع المصدر المالي.
- بوابة صلاحيات واشتراك وAccounting V2 من الخادم، مع idempotency وoptimistic concurrency وتدقيق التغييرات.
- قراءة Firestore لأعضاء المؤسسة المخولين فقط، ومنع الكتابة المباشرة على `budgets` و`cash_forecast_schedules`؛ الكتابة عبر API المحمي فقط.
- إدراج مجموعتي التخطيط في النسخ الاحتياطي والاستعادة مع تحقق صارم، مع إبقائهما خارج بصمة الإقفال المالي لأنهما غير مرحلتين محاسبياً.
- مسار API محمي: `GET /organizations/:orgId/reports/cash-forecast`.
