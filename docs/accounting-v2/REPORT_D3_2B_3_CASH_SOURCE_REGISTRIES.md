# تقرير D3.2b.3 — سجلات مصادر التوقع النقدي

## النطاق المنجز

- سجل مؤسسي محمي للمصروفات الدورية بتكرار أسبوعي أو شهري أو ربع سنوي أو سنوي.
- سجل للمدفوعات المجدولة الداخلة والخارجة مع الطرف والمرجع.
- تحقق صارم من الحقول والمبالغ والتواريخ والحالة، وتعارض إصدارات عند التعديل.
- تضمين المصادر النشطة فقط داخل أفق التوقع، مع ترحيل المتأخر المجدول إلى تاريخ الأساس.
- عدم إنشاء قيود يومية أو تغيير أرصدة من بيانات التوقع.
- إدراج السجلين في النسخة الاحتياطية المحمية، ومنع الكتابة المباشرة عبر Firestore.
- تحديث واجهة التوقع لتعرض التغطية وتسميات المصادر الأربع بصدق.

## الصلاحيات والسلامة

- الإدارة تتطلب `budget:manage`، والقراءة/التوقع تتطلب `budget:read` مع صلاحيات التقرير الحالية.
- الخطة يجب أن تدعم `accounting` و`advanced_reports`، والمؤسسة تستخدم Accounting V2.
- لا تمنح القواعد السوبر أدمن وصولاً مالياً موروثاً، ولا تسمح بكتابة SDK مباشرة.
- المصادر تخطيطية فقط؛ لا تُعد مصروفاً أو دفعة محاسبية منفذة.

- لا توجد واجهة إدارة للسجلين بعد؛ المرحلة التالية تضيف نموذج الإدارة والمزامنة واختبارات UI لهما.
- قبول Render مستقل ومعلق حتى نشر staging مطابق ومصادق عليه؛ لم يحدث نشر في هذه المرحلة.
- لا دمج، لا migration، ولا كتابة إنتاجية.
