# Firebase هو مخزن بيانات الأعمال الوحيد — قبول المصدر

الفرع: `codex/firebase-cloud-acceptance-fix-20261020` — [PR109](https://github.com/mistertee1/Sodaflow/pull/109)، للمراجعة والدمج بواسطة المستخدم. بدأ من main `0bd2f05d4121bad50be30249e8959c78bc039f01`، بعد دمج المستخدم [PR103](https://github.com/mistertee1/Sodaflow/pull/103) في20 أكتوبر. تفعيل الإنتاج مستقل وغير مكتمل.

## النتيجة في المصدر

- أزيل تشغيل الضيف وguestStore وقراءة/كتابة snapshot وبيانات المؤسسة وتفضيلات الواجهة من التخزين الدائم للمتصفح. البيانات القديمة تُترك دون حذف أو استيراد أو اعتماد عليها.
- Firebase Auth مدخل العمل. يحتفظ SDK بجلسة الدخول؛ Firestore يستخدم `memoryLocalCache()` فقط، بلا cache دائم لسجلات ERP. الذاكرة المؤقتة للواجهة ليست قاعدة بديلة.
- الـAPI المتحقق من الهوية والعضوية والاشتراك ينفذ المعاملات على Firestore وحده. فشل الاتصال لا يتحول إلى حفظ محلي أو لوحة أرصدة صفرية. الطلبات والردود تستخدم `no-store`.
- معرّفات منع التكرار محفوظة في Firestore ضمن metadata خاصة بالمستخدم/الشركة أو Super Admin الحصري. تشمل معرّفاً وبصمة وهوية ووقتاً، بلا كلمة مرور أو حمولة مالية. فحص العضوية/الإدارة داخل المعاملة؛ النية لا تمنح حق تنفيذ العملية.
- إقرار الاستلام يمسح النية المطابقة فقط. الرد القديم لا يمس نية أحدث، وفشل التنظيف أو مهلة4 ثوان لا يحول الحفظ المالي المؤكد إلى فشل. تبقى النية السحابية لإعادة المحاولة بعد reload.
- الباقات وحد100 فاتورة وصلاحيات الانتهاء والحساب الإداري الحصري والمحاسبة والهوية محفوظة. Rules لم تُفتح أو تُعدّل.
- اختبارات الواجهة تستخدم Firebase Auth اصطناعياً وخادم `createApi` حقيقياً وMemoryStore؛ فحوص القيود والأرصدة والمصادر والنقر المزدوج وإعادة التحميل باقية.

## إصلاح القبول بعد دمج PR103

CI main كشف فشلاً واحداً في حالة رأس المال والمسحوبات. رسالة نجاح الحركة الأولى ظلت ظاهرة أثناء تحقق المالك للحركة الثانية؛ فقرأها الاختبار كتأكيد جديد قبل اكتمال الحفظ.

في المصدر `bde2b6955d29e5ffdcf22ca2a56f5ad626ea98f6`:
- تمسح الواجهة النجاح السابق عند بدء مراجعة الحركة الجديدة، قبل التحقق من الهوية.
- يحتجز الاختبار طلب كل حركة قبل وصوله إلى الخادم، ويتحقق من غياب النجاح وثبات السجلات، ثم ينتظر إغلاق الحوار والتأكيد وحفظ سجل إضافي واحد. يحتفظ بفحص حركتين وقيدين بالضبط وقراءة التاريخ بعد reload ومنع غير المالك.
- تجربة مضادة على واجهة main قبل الإصلاح فشلت فعلياً: status واحد عند المراجعة الثانية، والمطلوب0. بعد الإصلاح نجحت حالتا المالك وغير المالك ضمن مجموعة الواجهة الكاملة. لا sleep أو إسقاط assertion أو تكرار تلقائي لاختبار كامل.
- تغيير التطبيق في PR109 سطر واجهة واحد؛ لا تغيير للحسابات أو القيود أو API أو Rules.
