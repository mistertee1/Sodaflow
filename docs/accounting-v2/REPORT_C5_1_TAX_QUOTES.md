# C5.1 — إعدادات الضرائب وأساس الحساب القابل للتخصيص

## المنفذ

- عقد إعداد ضريبة قابل للتخصيص حسب المؤسسة: الاسم/النطاق، الإصدار، النسبة، المبيعات أو المشتريات، الشمول أو الإضافة، التقريب، الاسترداد، الحساب، تواريخ الصلاحية والتفعيل.
- حساب نقي لضريبة المبيعات والمشتريات في العملة الأصلية ودفاتر SDG/USD، مع حفظ مجموع الأساس والضريبة والإجمالي دون فروقات.
- حساب ضريبة مبيعات مستحقة كالتزام دائن، وضريبة مشتريات مستردة كأصل مدين مستقل، ومعالجة غير المستردة كتكلفة.
- كشف فرق التحويل البسيط المحمّل على الأساس، وإثبات إعداد منسوخ لا يتأثر بتعديل لاحق للكائن الأصلي.
- منع إعدادات أجنبية أو مكررة، إصدارات قديمة، تاريخ خارج الصلاحية، حسابات معطلة/خاطئة، أسعار صرف غير صالحة، مبالغ بدقة غير مسموحة وحقول ضريبة أو رصيد مصطنعة.
- لا توجد نسب دولة ثابتة في الكود؛ نسب الاختبارات أمثلة حسابية فقط.

## التحقق

- نجحت 13 حالة متخصصة، بما فيها مصفوفة تحقق من المحافظة على مبالغ الدفاتر والعملات، وحالات التقريب والشمول والاسترداد والصفر والصلاحيات الحسابية للبيانات.
- نجح فحص Core محلياً. نتيجة الفحص الشامل وCI ستثبت بعد اكتمال commit المرحلة.

## الحدود والتالي

- هذه مرحلة عقد وحساب نقي فقط، لا تمنح صلاحية ولا تكتب أو تنشر أو تعدّل سلوك الضرائب الحالي للفواتير/المشتريات. مقدار الأساس هنا دخل حسابي؛ مرحلة الخادم التالية يجب أن تشتقه من مصدر المستند.
- لا توجد واجهة أو API أو حفظ إعدادات أو تقرير/إقفال ضرائب بعد. قبول Render غير قابل للتطبيق لهذه المرحلة غير المكشوفة.
- التالي C5.2a: حفظ إعدادات وإصداراتها بأوامر محمية وسجل تدقيق. ثم ربط المبيعات والمشتريات والمخزون والذمم والتصحيحات والمطابقة والنسخ الاحتياطي، وبعدها واجهة مركز الضرائب والفترات والتقارير.
- المستندات التاريخية تحتفظ بإثبات الإعداد والمبالغ الأصليين، ويجب إظهار النشاط القديم غير المصنف قبل قبول تقارير الضرائب.
- الفرع متراكم فوق PR46، والمراجعة والدمج للمستخدم. بقية C5/C6/D/E وExcel والقبول التجاري ما زالت مطلوبة.
