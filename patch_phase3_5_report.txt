1. ISSUE DIAGNOSIS & ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------
* Problem:
  Following the implementation of duplicate invoice prevention and transaction
  atomicity, users reported that the Invoice Modal ("إنشاء فاتورة جديدة") remained
  open after successful invoice creation, requiring manual dismissal.

* Root Cause:
  In `src/components/InvoiceFormModal.tsx`:
  The component interface declared `onInvoiceCreated: (invoice: Invoice) => void;`.
  However, in `src/App.tsx`, the modal was instantiated without providing this
  callback (`onInvoiceCreated` was undefined).
  In `handleSubmit`, the code executed:
    `onInvoiceCreated(created);`
    `onClose();`
  Because `onInvoiceCreated` was undefined, invoking it threw a runtime
  `TypeError: onInvoiceCreated is not a function`.
  This exception immediately aborted normal execution flow and transferred control
  to the `catch (err: any)` block, completely bypassing the `onClose()` invocation.
  Consequently, even though the invoice was successfully committed to Firestore,
  local state, inventory movements, and journal entries, the modal never closed.


2. ARCHITECTURAL IDENTIFICATION OF REACT STATE
--------------------------------------------------------------------------------
* Modal Visibility State:
  - Name: `isNewInvoiceOpen` (in `src/App.tsx`)
  - Setter: `setIsNewInvoiceOpen(boolean)`
  - Context: Paired with `prefilledCustomer` and `setPrefilledCustomer(Customer | null)`

* Component Props & Signature:
  - Component: `InvoiceFormModal` (in `src/components/InvoiceFormModal.tsx`)
  - Props:
    * `isOpen: boolean`
    * `onClose: () => void`
    * `onInvoiceCreated?: (invoice: Invoice) => void` (made optional)
    * `prefilledCustomer?: Customer | null`
    * `initialCustomer?: Customer`

* Submit Handler Flow:
  - Function: `handleSubmit(e: React.FormEvent)` in `InvoiceFormModal.tsx`
  - Result: `const created = await createInvoice({...})`

* Lifecycle Resolution Paths:
  [SUCCESS PATH]
  1. `await createInvoice(...)` executes atomic Firestore transaction & state update.
  2. Result verification: `if (created && created.id)` confirms valid invoice generation.
  3. Safe callback execution: `if (typeof onInvoiceCreated === 'function') onInvoiceCreated(created);`.
  4. State cleanup: `setErrorMessage(null); submissionLockRef.current = false; setIsSubmitting(false);`.
  5. Modal closure: `onClose()` triggers `setIsNewInvoiceOpen(false)`.

  [FAILURE PATH]
  1. Validation failure, Firestore transaction error, or network fault throws exception.
  2. Execution enters `catch (err: any)`.
  3. Error display: `setErrorMessage(err.message || 'حدث خطأ أثناء حفظ الفاتورة.')`.
  4. Unlock for retry: `submissionLockRef.current = false; setIsSubmitting(false);`.
  5. `onClose()` is NOT called. The modal remains open so the user can fix errors or retry.
