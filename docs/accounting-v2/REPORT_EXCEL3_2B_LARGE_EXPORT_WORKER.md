# تقرير Excel3.2b — عامل التصدير والملفات المؤقتة المؤمّنة

## النتيجة

أضيف عامل خادمي قابل للتشغيل كـRender Background Worker لمعالجة مهام Excel3.2a، وإنشاء artifact خاص مؤقت، وإصدار رابط قصير العمر بعد إعادة فحص الصلاحيات. لم يُنشر العامل ولم يُشغّل على بيانات إنتاجية.

## التنفيذ

- فهرس خادمي للمهام المعلقة، مع قراءة مرتبة ومحدودة إلى 25 عنصراً بدلاً من مسح الطابور كاملاً.
- مطالبة ذرية للمهمة تمنع عاملين من تنفيذها معاً، واسترداد claim متروك بعد 15 دقيقة ضمن حد المحاولات.
- توليد حزمة الشركة JSON للمالك الفعلي أو دفتر المحاسب Excel XML حتى 50 ألف قيد و25MB، من snapshot خادمي يعيد التحقق من العضوية والاشتراك والميزات والصلاحيات.
- حفظ خاص في Firebase Storage دون download token دائم. سجل المهمة يحتفظ بالمسار والاسم والنوع والحجم وعدد السجلات وبصمة SHA-256 فقط.
- endpoint مصادق عليه يعيد فحص العضوية الحالية والاشتراك والميزة والمنشئ/المالك ثم يصدر signed URL بحد أقصى خمس دقائق.
- انتهاء artifact بعد 24 ساعة وحذفه، مع فهرس تنظيف محدود وأحداث تدقيق COMPLETED/FAILED/EXPIRED.
- عند الإلغاء المتزامن بعد الرفع، لا تُنشر نتيجة النجاح ويحذف العامل الملف فوراً. رسائل الفشل المحفوظة عامة ولا تكشف تفاصيل Storage أو الخادم.
- العامل يستخدم Firestore مباشرة ويفشل مغلقاً؛ لا ينتقل إلى التخزين المحلي الاحتياطي عند فقد صلاحيات الخدمة.

## التحقق

- نجاح lint/core وbuild والتدقيق الأمني محلياً.
- اختبارات المطالبة الواحدة، رابط التنزيل القصير، حجب غير المنشئ، الإلغاء المتزامن، الفشل المعقم، إعادة المحاولة، انتهاء الملف، واسترداد العامل المتوقف.
- نتائج CI النهائية موثقة في `PROGRESS.json` وPR #96.

## القيود وما بقي

- لا توجد واجهة تعرض التقدم أو زر التنزيل بعد؛ تتبع Excel3.2c مع مهام الاستيراد الكبيرة وتجربة المراجعة.
- أمر `worker:large-export` جاهز للتكوين كخدمة عامل، لكن إنشاء/نشر خدمة Render أو ضبط أسرارها لم يُنفذ ولا يندرج ضمن إذن هذه المرحلة.
- قبول Render يتطلب deployment مطابقاً للالتزام، حسابات اصطناعية مخولة، واختبار الطلب/الإكمال/التنزيل/الانتهاء. CI ليس بديلاً عنه.
