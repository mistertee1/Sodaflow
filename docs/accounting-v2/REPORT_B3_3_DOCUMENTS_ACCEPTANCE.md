# تقرير B3.3 — المستندات المستقلة وقبول الدورة التشغيلية

تاريخ التقرير: 2026-10-07. **الكود منفذ والاختبارات المحلية الأساسية ناجحة؛ ينتظر CI الكامل والمراجعة البصرية النهائية.** الفرع `codex/accounting-v2-b3-documents-acceptance` يعتمد فرع المشتريات وPR #21، الذي اجتاز 172 وحدة/API و24 Firestore و37 واجهة. #21 يعتمد #20، والمستخدم وحده يراجع ويدمج.

## المنفذ

- أمر `correctionDocument.export` يجلب إشعار البيع/المردود أو رد العميل أو مردود الشراء أو استرداد المورد من المؤسسة الحالية، ويثبت المصدر الأصلي والقيود والتوزيع والتكلفة والسداد. لا يقبل HTML أو مستنداً أو تكاليف من الطلب. يتطلب صلاحية التصدير والقراءة المناسبة والاشتراك الحي والمحاسبة وV2 وسلطة الخادم/Rules حتى عند إعادة طلب محفوظ.
- يعيد قالباً محدداً يتضمن المنشأة والطرف والمصدر والبنود والمبلغ والتاريخ والسبب وقيد اليومية وتسلسل المصدر ومرجع العملية والمنشئ. سند النقد يشمل الحساب المالي وعملته وسعر الصرف والقيمة التاريخية والنقد بالدفترين وفرق الصرف. إشعار البيع يبين التخفيض والضريبة المعكوسة، والمردود يبين التكلفة الأصلية المستعادة. مردود الشراء يبين الائتمان الأصلي والمخزون الخارج وفرق WAC وجدول المنتجات المجمعة.
- أزرار PDF مستقلة في سجل تصحيحات الفاتورة والمورد، مع قفل فوري للإرسال ورسالة خطأ تحفظ السياق. التصدير يحصل على البيانات المحمية حديثاً عبر النقل الحالي، ويكتب `DATA_EXPORT_CREATED` مع نوع ومعرف المستند والمصدر والنسخة وعدد السجلات، دون تعديل المال أو البضاعة.
- القالب يستخدم عقد نص آمنة وخط العربية القائم، وصفحة A4 وأرقاماً معزولة في RTL وعمودين مستقلين للعملات. تكرر عناوين المستند والجدول وترقيم الصفحات، وتحافظ الآلية القائمة على البنود كاملة عند الانتقال بين الصفحات. وصف يشبه HTML يبقى نصاً ولا ينفذ. أزيلت قيمة الصفر السالبة من عرض فرق الصرف.
- اختبار الدورة كشف أن الاستعادة السابقة كانت تسقط سجل التدقيق الأصلي. أضيف `audit_archives` لحفظ الحدث الأصلي كاملاً ومعرفه ومؤسسته وبصمته والمنشئ ووقت/عملية الاستيراد، مستقلاً عن سجل المؤسسة الجديدة. معرف الأرشيف يشتق من المؤسسة الأصلية ومعرف الحدث، والبصمة تستخدم ترتيب مفاتيح ثابتاً عبر Firestore وبيئات التشغيل. الأرشيف لا يمنح عضوية أو ملكية.
- النسخة الحديثة تحمل `audit_schema_version: 1` وعدد أحداث التدقيق، وتحفظ عداد الأرشيف. حذف الأحداث أو الأرشيف دون تعديل أدلته يرفض الاستعادة؛ تعديل حدث مؤرشف يرفض فحص البصمة. الاستعادة الثانية تحفظ أصل الأحداث والبصمات دون تغيير مراجعها. الوصول API فقط بصلاحية التدقيق؛ يبقى SDK ممنوعاً، ولا تتغير ملكية المؤسسة المستهدفة.

## التحقق

نجح `npm run check` محلياً مع **177 اختبار وحدة/API** والأنواع والفحص الصارم وبصمة Rules والبناء. الحالات الجديدة تثبت إثبات مصدر التصدير والتدقيق وعدم تعديل الدفاتر، منع الطلب المحفوظ بعد انتهاء الاشتراك/تعليق المحاسب، منع سلطة المتصفح ومدخلات مؤسسة أخرى أو HTML وHTTP غير المصادق، ورفض المصدر المعدل.

الدورة المتكاملة تشمل شراء نقدي وآجل ومبيعات وتحصيل عميل جزئي ثم نهائي وسداد مورد جزئي ثم نهائي، وتصحيح السعر ومردود البيع ورد العميل، ومردود الشراء والاسترداد، وتحويل البنك ومصروف منه ومطابقته والجرد النقدي، والتقارير والميزان والمركز المالي والنسخ والاستعادة مرتين. المطابقة المالية والميزان متوازنان بعد كل نقطة، وAR/AP غير المخصص صفر، والمركز المالي بلا فرق. المستندات والقيود والمخزون والسداد والأحداث المؤرشفة تبقى مطابقة، مع مالك مستقل للمؤسسة الجديدة. سقوط أرشيف أو حدث وتغيير بصمته يرفض دون كتابة جزئية.

اختبارا PDF الجديدان نجحا محلياً قبل آخر تحسين للعرض: خمسة مستندات مستقلة من الواجهة مع ضغط مزدوج وتدقيق واحد، ومستند محفوظ من 100 بند بصفحات متعددة ونص آمن. تعاد مراجعة النسخة النهائية بعد عرض الضريبة والحساب المالي وتحسين عمود الوصف. أضيف اختبار Firestore فعلي للتصدير والاستعادة والبصمة بعد إعادة ترتيب الخرائط ومنع SDK والعزل. **CI الكامل لم يؤكد بعد**؛ المتوقع 177 وحدة/API و25 Firestore و39 واجهة.

## الحدود والخطوة التالية

- الإخراج يعيد استخدام محرك PDF القائم الذي يحول صفحات HTML إلى صور عالية الدقة داخل PDF؛ لا يدعي هذا الجزء نصاً قابلاً للبحث أو معيار PDF/A. إخفاء التكلفة والصلاحيات التفصيلية D، وحزمة المحاسب وExcel لها مراحلها.
- سقف استجابة مستند التصدير 650 KB. حد الاستعادة الذرية 350 سجلاً يشمل الأرشيف، و440 مع الفهارس؛ الأرشيف الفردي 650 KB، وحد طلب العمليات القائم يظل سارياً. الملفات الكبيرة تحتاج Jobs. النسخ القديمة بدون سجل تدقيق لا تعيد إنشاء أحداث لم تكن فيها؛ تبقى متوافقة عندما لا تدعي أرشيفاً مفقوداً. البصمة تحقق الاتساق ولا تمثل توقيعاً مستقلاً يصدق مصداقية نسخة خارجية اختلقت جميع أدلتها.
- قبول B التشغيلي لا يساوي سيناريو الجاهزية التجارية الكامل 94–98؛ فتح الأرصدة والإغلاق وإعادة الفتح والضرائب والأصول في C، والأبعاد والموافقات في D، والمساعدة في E وExcel1–4 وPRD50 متبقية. الخطوة التالية C1 للفترات والإغلاق وإعادة الفتح، بعد CI هذا الجزء.

لا تغييرات على Super Admin أو المصادقة أو المزامنة؛ إضافات Context تخص التصدير والمجموعات المحاسبية. لم يحدث دمج أو كتابة إلى main أو نشر تطبيق/Rules أو تغيير بيانات إنتاج.
