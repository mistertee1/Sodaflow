# تقرير Excel2.2a — عقد استيراد ومعاينة الأرصدة الافتتاحية

## النتيجة

أضيف قالب ومحلل XLSX آمن للأرصدة الافتتاحية يحول النقدية والعملاء والموردين والمخزون ورأس المال إلى عقد المعاينة المحمي الموجود. لا تنفذ هذه المرحلة أي كتابة أو ترحيل مالي، ولا تغيّر بيانات تاريخية.

## ما تم

- قالب رسمي ثابت: تعليمات وخمس أوراق مالية بعناوين مستقرة.
- حد ملف 2MB وحدود صفوف وأعمدة، مع بصمة SHA-256 واسم مصدر قابلين للمراجعة.
- رفض الصيغ والعناوين أو الأوراق المخالفة والعملات والتواريخ والدقة غير الصالحة والتكرارات وتعدد رأس المال وتجاوز 97 مصدراً.
- حفظ تواريخ الاستحقاق، العملة الأصلية، كمية وتكلفة المخزون، ومراجع المصادر دون اختراع FX أو حساب مقابل.
- تحويل الناتج إلى `OpeningInput` و`OpeningTerms` فقط للاستفادة من تحقق ومعاينة C2 الموجودين.

## الاختبارات

- 4 اختبارات جديدة تغطي جميع الأوراق، القالب وإعادة القراءة، الصيغ، العناوين، التكرارات، الحدود، الدقة، الاستحقاق ورأس المال.
- pretest: 8/8 لاختبارات master import وopening import.
- regression المحلي: 370/370 وحدة وAPI.
- lint وlint:core وbuild ناجحة.
- `npm audit --omit=dev --audit-level=high`: صفر ثغرات production.
- نتيجة CI الفعلية موثقة في `PROGRESS.json` على commit الكود الخاص بهذه المرحلة.

## الأمان والمخاطر المتبقية

- لا يوجد زر اعتماد أو أمر كتابة جديد في هذه المرحلة؛ parser لا يتجاوز عقد المعاينة/المالك القائم.
- Excel2.2b ما زالت مطلوبة لواجهة الرفع المحمية والصلاحيات وتسليم preview/commit والمزامنة وإعادة التحميل والمطابقة بعد الاستيراد.
- قبول Render مستقل ولم يُدّعَ؛ يلزم staging مصادق يطابق commit واستخدام مؤسسة اصطناعية فقط.
