# منع تكرار المنتجات

الحالة: المصدر منفذ والفحص المحلي ناجح؛ قبول Emulator والمتصفح قيد التنفيذ.

الفرع مبني من main `649ea3beb09b83a89eb45834f944625086d3135c` مع اندماج مصدر الدولار المقبول من PR125/128 (`bc43f5727ff9e79b9a11190251ef566190d83ee3` عبر `5c05e172c518c2dd663e5e79646590a87d57defa`). يحتفظ بتخزين ملفات العملاء المدمج في PR120. لم يكتب main.

## التغييرات

- الاسم موحد للمقارنة بعد المسافات وحالة الحروف والعلامات العربية الزخرفية وUnicode؛ أحجام المنتجات وأرقامها والحروف المختلفة تظل مميزة.
- حجز SHA-256 خاص بالشركة في معاملة الخادم نفسها يمنع سباق الإضافة وتغيير الاسم. فحص الكتالوج يغطي المنتجات القديمة بلا حجز، والحجز المتروك يسترد فقط بعد التحقق من صاحبه.
- لا يستطيع العميل كتابة الحجز أو المنتجات مباشرة وفق Rules الحالية. الخطأ HTTP409/duplicate_product واضح؛ تحقق فوري بالواجهة أيضاً.
- المكررات القديمة ومعرفاتها ومخزونها وروابط فواتيرها تبقى محفوظة، مع مرشح للمراجعة. يسمح بتعديل السعر/البيانات دون تغيير هوية قديمة. حذف منتج مرتبط بالمستندات يظل ممنوعاً.

## الاختبارات

`npm run check` محلياً:417 وحدة/API،16 توافق Netlify، وفحصي TypeScript والبناء؛ كلها ناجحة، بلا فشل أو تخطي. تشمل12 اختباراً جديداً للهوية والذرية والتزامن والحذف والاستعادة وعزل الشركات وHTTP. اختباران جديدان لـFirestore Emulator وأربعة سيناريوهات متصفح مضافة؛ نتيجتها معلقة حتى CI. الاختبارات المالية ببيانات اصطناعية فقط.

لا نشر أو ترحيل أو تغيير Rules/claims أو أسرار أو حسابات إنتاج. PR126 المحاسبي وcheckpoint الخاص به لم يتغيرا؛ lease محرر عند المراجعة. لا يدعي هذا التقرير أن الموقع المنشور تغير.
