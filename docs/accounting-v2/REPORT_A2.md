# تقرير A2 — تكلفة المخزون وCOGS

التاريخ: 2026-10-05. الفرع: codex/accounting-v2-a2-inventory-costing. الأساس: main عند 3b056a813b7c532a5a8d8dc9b53069fc6da11991 بعد دمج المستخدم A1 وSuper Admin. الحالة: منفذ، التحقق الكامل وCI قيد المراجعة؛ لا يُعتمد تجارياً الآن.

## المنفذ

- تكلفة المخزون بالقيمة الدفترية والمتوسط المرجّح للعملتين، مع دقة الكمية 6 خانات وSDG صفر وUSD خانتين، وحفظ فرق التقريب في آخر صرف/بند.
- إثبات تكلفة المخزون الحالي بواسطة Owner بوثيقة وسبب، وقيد مخزون/حقوق افتتاحية، دون تخمين من سعر البيع أو إعادة كتابة الفواتير القديمة.
- استلام نقدي/بنكي بقيمة موثقة وحساب سداد صحيح؛ فواتير المورد الآجلة ضمن B. الجرد يرحّل فرق القيمة تلقائياً إلى حساب تسويات المخزون.
- لقطة تكلفة ثابتة لكل بند وقيد COGS/مخزون داخل عملية إصدار الفاتورة نفسها. الإبطال يستعيد التكلفة الأصلية ويحافظ على القيد الأصلي، حتى بعد تغيير السعر أو المتوسط.
- منع البيع المؤرخ قبل آخر حركة تكلفة، ومنع إبطال فاتورة قديمة مجهولة التكلفة بعد إثبات تكلفة جديدة.
- تفعيل V2 بعد مطابقة مالية ومخزنية بواسطة Owner فقط. حقول التكلفة المحسوبة لا تُعدل عبر بيانات المنتج، وقيود المخزون/COGS اليدوية ممنوعة في V2.
- حفظ سلطة الكتابة في الخادم، مع تحقق قراءة فقط من بصمة قواعد Firebase المنشورة قبل كتابة V2/إثبات التكلفة/استعادة بيانات التكلفة. لا كتابة مباشرة من المتصفح ولا تغيير إعداد الإنتاج.
- توسيع المطابقة: الكمية، قيم الحركات، المخزون مقابل GL، مرجع القيد، ولقطات تكلفة الفواتير مقابل COGS. استعادة V2 مشروطة بالمطابقة والحماية، مع الحفاظ على ملكية وباقة الشركة المستهدفة.
- واجهة تكلفة/استلام/جرد وتفعيل واضحة، وعرض قيمة الجرد بالتكلفة الفعلية. الأرباح غير المكتملة تاريخياً يظهر عليها تنبيه؛ قائمة الدخل لا تعرض مجمل/صافي ربح كامل عندما تكون تكلفة الفترة مجهولة.
- تقرير الـAPI يستخدم دليل الحسابات الفعلي ويحترم الفترة المطلوبة، ويتضمن costs_complete. أضيف سجل قبل/بعد، دور المنفذ، السبب ومدخلات وثيقة التكلفة.

## التوافق وإصلاحات الدمج

حُفظ كود السوبر أدمن وقواعد منع الكتابة المباشرة وAPI المزامنة ومسار Netlify الجديد. لم يُرجع مسار كتابة Firestore القديم. راجعت الفشل في CI الخاص بآخر main: أعيد فحص توثيق البريد عند إنشاء المؤسسة، وضُبطت بيانات اختبارات الباقات على الحقول المركزية الجديدة، وأصبح اختبار المجانية يثبت حد 100 فاتورة إجمالاً عبر الشهور، بدون استرجاع الحد الشهري القديم. الاختبارات تقيس إعادة المحاولة مرة واحدة، وحق العضو الإضافي محفوظ في سياسة الباقة.

## التحقق حتى هذه النقطة

- check: نجحت الأنواع، strict core، اختبارات الوحدة السابقة و8 اختبارات A2، وبناء الواجهة والخادم؛ تمت إضافة اختباري API/تاريخ تكلفة بعد ذلك وإعادة الفحص جارية.
- npm audit --omit=dev: صفر ثغرات إنتاج.
- Playwright: اختبارا A2 نجحا محلياً (التفعيل/الاستلام/COGS على الموبايل، وتكلفة تاريخية مجهولة). باقي المجموعة تُراجع عبر CI.
- قواعد Firestore: اختبارات المنع ومبيعات الخادم المتزامنة تحت V2 محدثة. التشغيل المحلي يتطلب Java 21 والبيئة المحلية فيها 17؛ التحقق النهائي ينتظر CI المجهز بـ21.
- لا يوجد نشر، دمج بواسطة الإيجنت، تغيير بيانات إنتاج أو ترحيل أموال.

## الحدود والباقي

تطابق القواعد المنشورة وصلاحية قراءتها للخادم شرط تشغيلي؛ لا أدعي فحص قواعد الإنتاج أو نشرها. دعم تحقق قاعدة مسماة مؤجل ويُمنع تفعيلها دون إثبات؛ الإعداد الحالي يستخدم default. وجود رصيد مخزون GL قديم دون أساس تكلفة موثق يحتاج معالجة يراجعها المالك، ولا يُضاف رصيد افتتاحي مكرر. تكلفة الماضي المجهولة لا تُصلح آلياً. كشف/إخفاء التكلفة التفصيلي حسب صلاحيات جديدة ضمن D؛ حد الاستعادة الذرية 350 سجل ما زال قائماً حتى مراحل وظائف الترحيل.
