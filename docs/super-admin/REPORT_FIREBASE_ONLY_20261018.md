## التغييرات

- إزالة تشغيل الضيف وguestStore ونسخة snapshot المحلية واختيار المؤسسة/تفضيلات الواجهة من localStorage. أي بيانات قديمة تُترك كما هي دون تشغيل أو حذف أو استيراد.
- Firebase Auth هو مدخل العمل. جلسة الدخول يديرها Firebase SDK، وFirestore يستخدم memoryLocalCache فقط. لا حفظ دائم لبيانات الشركات في المتصفح.
- تحميل السجلات والمعاملات يتم عبر API يتحقق من الهوية والعضوية والاشتراك، ويستخدم Firestore وحده. عند تعذر التحميل الأول يظهر خطأ اتصال واضح بدلاً من لوحة أرصدة صفرية أو بيانات قديمة.
- إضافة `Cache-Control: no-store` للـAPI و`cache: no-store` للطلبات.
- نقل منع التكرار إلى مستندات Firestore خاصة `organizations/{id}/operationIntents/{hash}` و`platformOperationIntents/{hash}`. تشمل معرّفاً وبصمة وهوية ووقتاً فقط، بلا حمولة مالية أو كلمة مرور.
- تحقق صلاحية داخل كل معاملة metadata، وعزل المستخدم/الشركة/الإدارة، وحد طلبات. نية إعادة المحاولة لا تمنح حق تنفيذ؛ المعاملات المحمية لا تزال تخضع لفحوص Operations/PlatformBilling.
- إقرار الاستلام ينظف النية المطابقة فقط؛ رد قديم لا يمس نية أحدث، وفشل التنظيف لا يحوّل الحفظ المؤكد إلى فشل مالي.
- نقل اختبارات واجهة المحاسبة من قاعدة الضيف إلى createApi الحقيقي مع MemoryStore وFirebase Auth اصطناعي. فحوص الأرصدة والقيود والمصادر ومنع التكرار باقية، وإعادة التحميل تقرأ الخادم نفسه. التحقق الحساس للمالك يستخدم مسار Firebase reauthentication بدلاً من تأكيد ضيف محلي.
- السوبر أدمن والباقات وحد 100 فاتورة وصلاحيات الاشتراك والمحاسبة والهوية محفوظة. Rules لم تُفتح أو تتغير.
