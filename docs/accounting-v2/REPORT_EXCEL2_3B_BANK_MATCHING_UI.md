# تقرير Excel2.3b — واجهة استيراد كشف البنك والمطابقة اليدوية

## النتيجة

اكتملت واجهة رفع كشف البنك CSV/XLSX داخل نافذة المطابقة البنكية المحمية، مع بقاء الملف محلياً بلا كتابة مالية حتى يراجع المستخدم الصفوف ويطابق كل صف يدوياً ثم يستعمل أمر الحفظ الذري القائم. المرحلة محفوظة في PR #93 فوق PR #92 ولا تتضمن دمجاً أو نشراً أو migration.

## ما تغير

- تنزيل قالب كشف البنك الرسمي من نافذة المطابقة.
- رفع CSV/XLSX بعد تحديد الحساب والفترة والرصيدين، وتحليل الملف بعقد Excel2.3a وعملة الحساب.
- عرض اسم الملف وعدد الصفوف والفرق الختامي وبادئة SHA-256.
- إدخال الصفوف في مسودة المطابقة بلا أي مطابقة تلقائية؛ يختار المستخدم حركة الدفتر لكل صف.
- إهمال نتيجة التحليل المتأخرة إذا تغيرت المؤسسة أو المستخدم أو الحساب أو الفترة أو الأرصدة.
- إبقاء `bankReconciliation.create` مسار الحفظ الوحيد، بلا API أو Firestore collection أو Rules جديدة.

## الصلاحيات والسلامة المالية

- الواجهة تعيد استخدام الحماية القائمة للمطابقة البنكية ولا تمنح صلاحية جديدة.
- Viewer لا يكتشف أدوات المحاسبة المحمية، والمحاسب المخول فقط يصل إلى التدفق القائم.
- الرفع لا يكتب قيداً أو مطابقة أو staging في الخادم، ولا يخمن حساباً أو FX، ولا يطابق تلقائياً.
- منع تكرار حركة الدفتر والفرق الختامي والتحقق من الفترة والمبلغ تستمر عبر عقد المعاينة وواجهة المطابقة القائمة.

## المخاطر والمتبقي

- قبول Render مستقل ومعلق حتى تتوفر نسخة staging مصادق عليها ومطابقة للالتزام؛ لا تعد نتائج CI دليلاً على هذا القبول.
- الملفات الكبيرة، التصدير الكامل، سجل العمليات، presets والمهام الخادمية المؤقتة تقع في Excel3.1 وExcel3.2.
- ترتيب الدمج: PR #92 أولاً ثم PR #93. المستخدم يراجع ويدمج؛ لم يُفعّل auto-merge.
