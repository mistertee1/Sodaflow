# تقرير C2.2b.1 — معاينة الأرصدة المحمية من الخادم

تاريخ التقرير: 2026-10-08 UTC. الفرع `codex/accounting-v2-c2-opening-preview` تابع لآخر PR26 بعد نجاح CI. **معاينة خادمية بلا كتابة أرصدة، وليست إكمال مساعد البداية أو الترحيل.**

## التنفيذ

أضيف `POST /api/organizations/:orgId/opening-balances/preview`، بمدخلات `input` و`terms` فقط. يعيد الخادم قراءة مجموعات النشاط الفعلية وMasters في معاملة قراءة، ثم يحسب أهلية المؤسسة ومعاينة العملتين والمخزون ورأس المال والفرق والاستحقاقات. لا يقبل counters أو snapshot أو journal_id أو auth_time أو hash من العميل.

صلاحية `opening:preview` محصورة في Owner الفعلي أو Accountant بعضوية نشطة. الادعاء Super Admin لا يحوّل المستخدم إلى مالك المؤسسة، وAdmin/Sales/Cashier/Viewer لا يحصلون على هذه المعاينة. تطبق العضوية والبريد المؤكد وحالة المؤسسة والاشتراك الحالي والباقة الحالية وميزة المحاسبة، وmulti_currency للسياسة المزدوجة، وinventory_tracking عند وجود مخزون. لا يغيّر الاختبار منطق الباقات المركزية؛ يختبر `plans/{planId}` كمصدر الميزات الحالي، ولا يثق بنسخة features القديمة في meta/subscription.

تتطلب المعاينة V2 وقواعد الخادم المعتمدة، وتمنع browser store. فشل قراءة مجموعة أو التحقق من قواعد V2 يمنع نتيجة أهلية كاذبة. كل طلب يعيد التحقق، ولا توجد نتيجة مخزنة أو عدّاد يتجاوز تغير الصلاحية أو الباقة.

يلزم وجود فترة محاسبية تغطي تاريخ الافتتاح وتسمح بعملية عادية؛ لا يتجاوز الافتتاح soft/hard close أو القفل القديم أو تاريخاً مستقبلياً حسب يوم المؤسسة. تُعاد هوية الفترة وإصدارها وحالتها؛ لم تتغير الفترات عند المعاينة.

المعاينة تسمح بعرض فرق Opening Equity قبل تدوين سبب مراجعته، وتبقي `equity_review_complete=false` ظاهراً. المصنع الخاص بإثبات الترحيل ما زال يرفض الفرق دون سبب. ترجع البصمة SHA-256 للأساس الحسابي المصغر والفترة والقفل والدقة، وتتغير عند تغير القيم أو الربط أو إصدار الفترة. ترتيب Masters لا يغيرها. الوقت والهوية ليسا جزءاً من البصمة؛ **البصمة فحص حداثة فقط ولا تمنح موافقة أو صلاحية ترحيل**. لا ترجع snapshot أو Masters أو هواتف الأطراف أو ملاحظاتهم، وHTTP يستخدم `Cache-Control: no-store`.

## التحقق

نجح `npm run check`: **219 وحدة/API** مع 8 اختبارات جديدة، والأنواع والفحص الصارم والبناء. بعد ضبط الحد البنيوي المبكر للطلب، أعيد الفحص الصارم واختبارات المعاينة الثمانية بنجاح. تشمل الحالات ثبات المخزن وبصمة المجموعات مع الوقت/ترتيب المصادر، فرق الافتتاح غير المراجع، Owner/Accountant وبقية الأدوار والعضوية والبريد، browser/server authority والقواعد وفشل القراءة، تغير الباقة المركزية والميزات وانتهاء/تعليق المؤسسة وV2، الفترة والقفل والتاريخ، تغيّر الأساس وcounters صفرية كاذبة، تهيئة منتج صفرية فعلية، استحقاق مستقل وخصوصية البيانات، وHTTP المصادق وحقوله المحمية وإبطال التخزين المؤقت. أضيف اختبار Firestore فعلي للمعاينة الجديدة دون كتابة أرصدة، ولربط Owner/Accountant، ومنع SDK عن مجموعات الافتتاح، وتغير الباقة والفترة. فحصه الصارم ناجح؛ التشغيل الكامل ينتظر CI ببيئة Java21. البيئة المحلية Java17 ولا تحتوي emulator cache، لذلك لم يُنسب نجاح emulator محلي لهذا الفرع.

أساس [PR26](https://github.com/mistertee1/Sodaflow/pull/26) أصبح جاهزاً بعد [CI37716137528](https://github.com/mistertee1/Sodaflow/actions/runs/37716137528): 211 وحدة/API و26 Firestore و44 واجهة وصفر ثغرات إنتاج على `4de1194d215c3e003b46049753a5da80aa8f5d12`. PR25 أيضاً جاهز بنتيجة 199/26/44. هذه النتائج مستقلة عن CI المعاينة الجديد.

## ما تبقى

C2.2b.2 سيضيف أوامر ذرية لافتتاح المؤسسة وتسوية الأطراف: إعادة قراءة وحساب وبصمة حديثة عند commit، Owner الفعلي بتحقق حديث وسبب للافتتاح، الصلاحيات/الاشتراك/الميزات والفترة وidempotency قبل cached retries، إثبات رصيد النقدية عند الصرف وتواريخه اللاحقة، تحديث المخزون وWAC والأرصدة والتدقيق والعدادات، ودمج المصادر في التقارير الحالية وAR/AP/Inventory↔GL والعملتين والاستعادة. يجب تطبيع الأساس المتداخل للمؤسسة المستعادة وإثبات counts وإسقاط المصادر والتدقيق؛ لم ينفذ ذلك في هذا الفرع.

C2.2b.3 واجهة المساعد والتسويات، ثم C2.3 رأس المال والمسحوبات. بقية C وD/E وExcel1–4 وشروط الجاهزية التجارية ما زالت متبقية. لا يوجد endpoint للترحيل في هذا الفرع ولا إنشاء أموال أو قيود من المعاينة. لم تتغير واجهة Super Admin أو منطق المصادقة/المزامنة أو Firestore Rules، ولم يحدث دمج/كتابة main أو نشر أو تغيير بيانات إنتاج. تغييرات server/api.ts وRBAC وOperations إضافات محاسبية محدودة تحفظ المسارات والمنطق القائم.

خطة الربط التالية ومواقع تعديل caches والتقارير ومتطلبات المطابقة والاستعادة محفوظة في [C2_OPENING_INTEGRATION.md](C2_OPENING_INTEGRATION.md). هذه خطة تحقق وتنفيذ، وليست ادعاء اكتمال الترحيل.
