# تقرير Excel2.3a — أساس استيراد كشف البنك CSV/XLSX

## النتيجة

أضيف عقد معاينة محلي وآمن لكشوف البنك بصيغتي CSV وXLSX فوق فرع Excel2.2b. لا تنشئ هذه المرحلة قيداً أو مطابقة أو جلسة خادم، ولا تغيّر أي بيانات مالية. PR #92 متراكم فوق PR #91 ويجب دمجه بعده.

## المنفذ

- قالب XLSX رسمي بورقتي `Instructions` و`Statement`، وعناوين ثابتة: `id,date,direction,amount,reference,description`.
- قارئ CSV يدعم الاقتباس والفواصل داخل النص، وقارئ XLSX يحتفظ بدليل الصيغ لكي يرفضه العقد.
- بصمة SHA-256 للملف، حد 2MB، وحد 500 حركة.
- تحقق صارم من امتداد الملف والعناوين والفترة ومعرّفات الحركات واتجاهها ودقة SDG/USD والتكرار والصيغ والنصوص القابلة للتفسير كصيغ.
- ملخص معاينة يحسب الوارد والصادر والرصيد الختامي المحسوب والفرق مع ختامي الكشف.
- الناتج يصرّح بـ`staging_preview` و`requires_manual_matching=true` و`writes_financial_data=false`.

## الاختبارات

- 5 اختبارات جديدة: الرصيد المتطابق، الفرق المرئي، الحالات المرفوضة، CSV المقتبس والبصمة، وقالب XLSX مع رفض الصيغ.
- GitHub Actions run `38894360112` على commit `80b094a422d31aa440d9f392644bff855f46c02e`: نجح.
- 13 pretest، و370 وحدة/API، و35 Firestore Emulator، و89 UI regression، وصفر ثغرات production.
- TypeScript وcore rules وproduction build نجحت.

## الحدود والمخاطر

- لا توجد واجهة رفع أو تنزيل القالب داخل شاشة المطابقة بعد.
- لا يوجد staging خادمي ولا صلاحية جديدة ولا أمر حفظ؛ لا يمكن لهذه المرحلة تعديل الأرصدة أو المطابقات.
- لا توجد مطابقة آلية. Excel2.3b يجب أن يربط الملف بحركات دفتر الحساب المحدد ويترك الاختيار يدوياً، ثم يستعمل أمر `bankReconciliation.create` الحالي فقط بعد المراجعة.
- قبول Render مستقل ومعلق؛ نسخة staging المسجلة لا تطابق commit المرحلة ولم تُنفذ كتابة سحابية.
