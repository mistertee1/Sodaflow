# Excel4.1d.3b.4 — الاعتماد الذري للمشتريات التاريخية

التاريخ: 2026-10-21. يستكمل هذا التقرير مسودة PR #114 والتقرير WIP السابق. لا يثبت جاهزية تجارية للنظام كله.

## النتيجة

- حفظ فواتير المورد والسداد والاستلام وقيود AP/المخزون/الضريبة/FX وتحديث المورد والمنتج وحجز المرجع والجلسة والتدقيق ذرياً.
- مطابقة البصمات والسياق الحي، ثم baseline صفري ومطابقة الحالة المقترحة قبل أي كتابة، مع idempotency وحد 400 كتابة مالية.
- إثبات ضريبة الشراء من السياسة التاريخية المجمدة وسلسلة إصداراتها؛ مطابقة توزيع كل بند بقيم المصدر دون اختلاق فروق تقريب.
- حُل عائق ضريبة الشراء بإعادة دمج العمل المتكامل في PR #53 بدمج Git حقيقي؛ لم تُعطل مطابقة التصحيحات ولم يُحذف source_event_sequence لتجاوزها.
- روجعت تعارضات الدمج: حُفظت أبعاد D1 على فاتورة الشراء وأطراف القيد، وموافقة استرداد المورد في D4، واختبارات Excel الأحدث. أُعيد إدراج اختبارات الضرائب والاستعادة التي غابت عن المسار الحالي.

## التحقق المحلي

- `npm run check`: ناجح، TypeScript + core rules + 73 Excel/import + 381 وحدة/API + البناء.
- اختبارات الشراء التاريخي تثبت الحفظ وإعادة الطلب، rollback عند حجز المرجع أو الرجوع الزمني، الضريبة المستردة، ورفض سلسلة hash معدلة دون أي كتابة جزئية.
- سيناريو USD شامل بضريبة 15% وبندين لنفس المنتج ودفعتين بأسعار 2550/2600 مقابل سعر فاتورة 2500: استلام واحد، FX خسارة 4000 SDG، AP متبقٍ 65 USD/162500 SDG.
- بعد تغيير السياسة إلى 20% يظل الإصدار الأصلي 15% محفوظاً. مردود البند الأول يعكس 6 USD ضريبة و46 USD من التزام المورد، ثم تنجح الاستعادة إلى مؤسسة أخرى والمطابقة الصارمة.
- نتيجة CI للرأس المنشور تسجل في PROGRESS.json؛ لا تُفترض نتيجة Emulator أو Playwright قبل ظهورها.

## الحدود والباقي

- لا خلط للبيع والشراء في جلسة واحدة؛ لا أبعاد غير مرحّلة؛ لا شراء أقدم من آخر تكلفة موثقة دون replay كامل.
- عقد الضريبة المنفصلة الحالي يقبل المستردة فقط؛ الضريبة غير المستردة تحتاج دليلاً يوضح تحميلها على المخزون.
