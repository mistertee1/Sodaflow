# تنفيذ Super Admin في SudaFlow

المستودع المرجعي: `mistertee1/Sodaflow`. العمل يبدأ من أحدث `main` ويحتفظ بالمحاسبة والهوية وإصلاحات المزامنة. طلب 2026-10-05 يعتمد الاختبارات قبل دمج كل مرحلة، ويلغي قيد عدم الاختبار السابق لهذا المسار.

| المرحلة | النتيجة | بوابة القبول قبل الدمج |
| --- | --- | --- |
| 0 — المراجعة | إثبات الحالة الحالية وخطة قابلة للاستئناف | توثيق الاختبارات الحالية والفشل والعوائق دون ادعاء جاهزية الإنتاج |
| 1 — الهوية والصلاحيات | تحقق البريد، فصل Super Admin عن Owner/Admin، جلسة إدارة آمنة | رفض الهوية غير المؤكدة، claim وحده أو registry وحده لا يكفيان، منع الوصول المالي لشركة غير مملوكة، regression الحالية |
| 2 — إدارة الاشتراكات والباقات | حالات وتواريخ وتجديد وتمديد وتغيير باقة وتجربة مرة واحدة وسجل ذري | idempotency وrevision والتزامن والفشل الذري، فرض 100 فاتورة مدى الحياة ومقعد موظف واحد، features مباشرة من الباقة، منع التجاوز |
| 3 — لوحة الإدارة | Dashboard/Companies/Subscriptions/Plans/Audit RTL بنفس الهوية | اختبارات UI لدخول الإدارة والرفض والبحث والتصفية والحفظ والفشل وإعادة المحاولة والبيانات الصحيحة؛ build وTypeScript |
| 4 — القواعد والترحيل | Rules منسجمة مع الخادم وخطة ترحيل تحفظ البيانات | Emulator فقط، منع الكتابة المباشرة وتغيير الاشتراك، منع tenant أجنبي، القراءة التاريخية عند الانتهاء، gate الـ features؛ تحقق الترحيل دون إنتاج |
| 5 — تفعيل الإنتاج | API وFirestore جاهزان، ترحيل معتمد، UID إدارة معين، نسخة حية صحيحة | صلاحية وصول فعلية، معاينة ونسخة احتياطية، نشر منسق ثم دخول ومزامنة حساب فعلي؛ هذه المرحلة مستقلة عن نجاح المصدر |

## الاستئناف وتنسيق العمل

- اقرأ `PROGRESS.json` و`REPORT.md` وأحدث main قبل كل جولة. لا تعتمد على بقاء مجلد التنفيذ أو node_modules في السحابة.
- احترم `activeRunId` و`leaseUntil` لتجنب جولة متزامنة. حرّر lease عند التسليم؛ إذا انتهت lease استأنف من آخر commit وفرع محفوظ.
- احفظ العمل غير المدمج في فرع واضح، واكتب أسماء الملفات المملوكة للمرحلة. لا تستخدم force push. إذا تغير main فراجع الملفات المتقاطعة وأعد الاختبارات المناسبة قبل الدمج.
- أنجز المرحلة واختبرها، ثم ادمج المصدر الذي اختبرته فقط. سجّل الأدلة والنتيجة والحدود، وابدأ المرحلة التالية دون سؤال روتيني.
- اختبارات الكتابة تستخدم MemoryStore أو مشروع Emulator `demo-sudaflow`. لا تختبر بإنشاء فواتير أو مدفوعات فعلية في الإنتاج.
- عند بقاء عوائق خارجية فقط، حرّر lease وعلّق الأتمتة وأرسل تقريراً واضحاً. لا تكرر طلب الدخول الذي رفضته المراجعة التلقائية دون تصريح جديد.
