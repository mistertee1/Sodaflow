# تقرير Excel4.1d.2 — staging المحمي لأدلة المستندات التاريخية

## النتيجة

اكتملت طبقة staging المحمية للفواتير والمشتريات التاريخية في PR #106، مكدسة فوق PR #105. لا تنشئ هذه المرحلة مستندات مالية أو دفعات أو مخزوناً أو قيوداً.

## المنفذ

- إلزام كل صف invoice/purchase بدليل أصلي كامل قبل staging.
- اشتقاق العملاء والموردين والمنتجات والحسابات من بيانات المؤسسة الحية على الخادم.
- رفض الأدلة المفقودة أو الزائدة أو غير المطابقة للصف قبل أي كتابة.
- حفظ نسخة مستقلة من الأدلة وبصمة SHA-256 داخل staging.
- إبقاء الإنشاء الأصلي والدفعات والمخزون والقيود للمرحلة Excel4.1d.3.
- تحديث regression ليتوقع الرفض المبكر الصحيح عند غياب الدليل، مع إثبات عدم وجود كتابة جزئية.

## التحقق

- الاختبارات المحلية المتخصصة: 8/8 ناجحة.
- CI للكود والإصلاح: ناجح — run 39217835917 على commit ae41f1dcd9485cdbf9418b49e3084275f1ab5af9.
- نجحت بوابات npm check وnpm audit --omit=dev وFirestore Emulator وPlaywright UI.
- لا توجد كتابة إنتاجية أو migration أو نشر أو دمج.
- قبول Render مستقل ومعلق حتى توافر staging مطابق ومصادق عليه.

## ترتيب الدمج

PR #106 يعتمد على PR #105؛ يجب دمج #105 أولاً، ثم مراجعة ودمج #106 يدوياً.

## المخاطر والمتبقي

الأدلة أصبحت محمية في staging، لكن لم تُنشأ بعد المستندات الأصلية أو الدفعات أو حركات المخزون أو قيود GL. المرحلة التالية Excel4.1d.3 تنفذ الاعتماد الذري والمطابقة والحماية من التكرار والتغيير.
