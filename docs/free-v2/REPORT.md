## التغيير

المجانية الحالية لا تستعلم عن باقة أو اشتراك أو توقيع قديم. كل الميزات متاحة وحدود الاستخدام Number.MAX_SAFE_INTEGER، دون سقف100 أو999999 في إسقاط الاشتراك. تُحفظ العقود القديمة والعدادات والأدوار دون ترحيلها أو تفعيلها. تسعة مسارات تقارير V2 كانت تعيد تشغيل قيود الباقة والعضوية رغم توقفها؛ أصبحت ترث سياسة الإصدار، وكذلك معاينة الاستيراد المتداخلة.

إدارة الجداول والعامل والتنزيل وحزمة الشركة ترث سياسة المجانية نفسها مع فحص Auth الفعلي ودور التصدير الحقيقي والمالك ونطاق المؤسسة وإلغاء العضوية والسياسة وTTL. لا تتحول ترقية الدور المؤقتة وقت إيقاف ضوابط المنصة إلى إذن لتصدير بيانات مالية خاصة. لم تتغير مؤقتات العامل ولا تفعّل تنفيذاته الدورية.

الشركة الجديدة من API الإنتاج تُنشأ مع accounting_version:2 فقط بعد قراءة Rules المنشورة والتحقق من بصمتها المقبولة، مع COA وأرصدة فارغة ومطابقة؛ فشل الإثبات لا يترك مؤسسة جزئية. إعادة إنشاء معرّف مؤسسة قديمة لا ترقيها تلقائياً. تفعيل المؤسسة المستخدمة يحتفظ بوثيقة تكلفة المخزون ومطابقة الدفترين؛ لا تكاليف مصطنعة أو تعديل للتاريخ.

الإعدادات تعرض «سودافلو مجاني100٪» بلا طلب ترقية. Super Admin وإدارة الاشتراك وحصص الباقات متوقفة في السياسة الحالية؛ لا حذف للأرصدة أو العضويات أو سجل العقود.

## نشر Rules

مسار النشر القديم كان ينفذ billing:migrate --apply قبل Rules ويمكنه bootstrap مسؤول. حُذفت هاتان الخطوتان من نشر القواعد: لا تفعيل باقات أو claims أو تغيير حسابات. workflow الجديد يفحص الأنواع والوحدات/HTTP والتشغيل والبناء والثغرات وFirestore demo-sudaflow والواجهة، ثم ينشر Firestore Rules والفهارس فقط إلى sodaflow، ويتحقق بعدها من تطابق القواعد عبر Admin SDK. لا وصول عام أو تغيير للقواعد لتجاوز بصمة V2.

هناك trigger محدود إلى فرع المراجعة الحالي وملف DEPLOY_REQUEST.json، يستعمل فقط بعد قبول المصدر وتسجيل الطلب المصرح به من المستخدم. لا تشغيل له قبل إضافة الطلب. يتطلب سر Firebase موجوداً في GitHub ولا يقرأ أو يسجل قيمته. لا مفاتيح في المصدر ولا إعادة طلب دخول أو كلمة مرور. لا يُستنتج نجاح النشر من نجاح البناء أو المحاكي.
