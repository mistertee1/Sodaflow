1. ISSUE SUMMARY & ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------
* Reported Error:
  "Error updating product in Firestore Function setDoc() called with invalid
  data. Unsupported field value: undefined (found in field description in
  document organizations/org-s3jXdh7OcweCABrJajFPeYrgd4I2/products/...)"

* Root Cause:
  1. In `src/components/ProductsView.tsx`, when optional form fields (such as
     `description` and `category`) were left empty or blank, the submit handler
     evaluated them as `description.trim() || undefined`.
  2. The Google Cloud Firestore JavaScript SDK strictly rejects JavaScript objects
     containing fields with `undefined` values during `setDoc` or `updateDoc` calls,
     throwing an uncaught exception:
     "Function setDoc() called with invalid data. Unsupported field value: undefined".
  3. Similar patterns existed across customer, settings, expense, accounting, and
     payment views, leaving the application vulnerable to runtime Firestore failures
     whenever optional inputs were cleared or omitted.


2. REMEDIATION & ARCHITECTURAL IMPLEMENTATION
--------------------------------------------------------------------------------
* Layer 1: Global Firestore Engine Configuration
  - File: `src/lib/firebase.ts`
  - Added `ignoreUndefinedProperties: true` to the `initializeFirestore` options.
  - This informs the Firestore client to ignore `undefined` attributes globally
    instead of throwing fatal validation errors.

* Layer 2: Recursive Deep Data Sanitizer
  - File: `src/lib/firebase.ts`
  - Created and exported `cleanFirestoreData<T>(data: T): T`.
  - Recursively traverses objects and arrays, stripping any key whose value is
    strictly `undefined` while preserving Dates, primitives, and valid falsy values.

* Layer 3: Context Mutation Enforcement
  - File: `src/context/AppContext.tsx`
  - Wrapped all payloads passed to `setDoc`, `updateDoc`, and atomic transaction
    `txn.set` with `cleanFirestoreData(...)` across:
    * `addProduct` & `updateProduct`
    * `addCustomer` & `updateCustomer`
    * `createInvoice` (including journal voucher and inventory movement writes)
    * `updateInvoice`
    * `recordPayment`
    * `addExpense`
    * `syncAllToCloud` (all bulk batch sync entities)

* Layer 4: View-Level Clean Fallbacks
  - Audited and updated UI forms to supply safe default empty strings `''`:
    * `src/components/ProductsView.tsx` (description, category)
    * `src/components/CustomersView.tsx` (email, address, notes)
    * `src/components/SettingsModal.tsx` (address, logo_url, bank_details)
    * `src/components/PaymentModal.tsx` (reference_number, notes)
    * `src/components/ExpensesView.tsx` (notes, receipt_image)
    * `src/components/AccountingView.tsx` (name_en, description)
