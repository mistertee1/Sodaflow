# Excel4.1e.2c.1 — أساس المعاينة الخادمية دون كتابة

2026-10-23 — PR122 تابع لـPR121؛ المستخدم وحده يراجع ويدمج.

## المنفذ

مسار POST /organizations/:orgId/historical-import/preview مصادق عليه، no-store، يرفض query filters وحقول الطلب الزائدة. الخدمة تتطلب سلطة server وتعيد تشغيل historicalImport.commit الحقيقي داخل معاملة قراءة واحدة مع إسقاط set/delete جميعاً. تعيد dry_run=true وproposed_result/proposed_changes، ولا تحفظ الجلسة أو المصادر أو العداد أو التدقيق أو إيصال idempotency. يظل وصف committed داخل proposed_result اقتراحاً فقط وليس حالة محفوظة. يرفض معرف عملية مستعملاً بالفعل بدلاً من إعادة نتيجة محفوظة قديمة.

يعاد التحقق من العضوية والصلاحية والاشتراك وV2 وإثبات Rules، بصمات الصفوف والسياق وأدلة المستندات، الضريبة وسلسلة إصداراتها، المراجع المحجوزة والفترات والمطابقة والتكلفة عبر نفس مسار الاعتماد، دون تكرار منطق مالي مستقل.

## التحقق

نجح npm run check محلياً: TypeScript وlint:core و82 Excel/import و382 وحدة/API والبناء، صفر فشل/تخطي. تشمل الاختبارات الجديدة native journal/sales/purchase مع مخزن اختبار يرمي خطأ عند استدعاء set/delete، تطابق التخزين قبل/بعد، بقاء operationId متاحاً للاعتماد الحقيقي اللاحق، ورفض استخدامه بعد الحفظ الحقيقي. تشمل رفض تعديل البصمة وإغلاق الفترة بعد staging، السلطة المحلية، غياب Rules verifier والعضوية الأجنبية والحقول الزائدة. HTTP يثبت المصادقة ورفض الفلاتر وno-store. البيانات محلية MemoryStore؛ متحقق Rules محاكاة صريحة، وليست قبول Firebase حي. CI/Firestore/Playwright لهذا الرأس لم تُثبت بعد.

## الحدود والتالي

هذه مقدمة جزئية لـExcel4.1e.2c، وليست اكتمال الاعتماد المالي. لا ربط للمعاينة في AppContext/واجهة المصنف بعد، ولا بصمة موافقة نهائية تربط حالة المؤسسة والأثر المقترح بعملية الاعتماد. يلزم إضافة ذلك واختبارات تبديل المؤسسة/تغير الحالة وإعادة المحاولة، ثم قبول Firebase السحابي المستقل ومراحل migration/auditor/scheduled exports المتبقية. لا وصف جاهزية تجارية أو اكتمال الوثيقة. لا main write/merge أو نشر أو قواعد Firebase أو بيانات إنتاج أو تعديل Super Admin/المزامنة.
