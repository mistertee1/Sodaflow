# تقرير C3.1c — موصلات عملة المصدر الموثوقة

## النتيجة

أصبحت معاينة إعادة تقييم العملة تشتق عملة المصدر لكل طرف نقدي من سجلات الخادم نفسها، ولا تقبل `native_source_allocations` من الطلب أو من لقطة قابلة للتزوير.

## ما نُفّذ

- موصلات الفواتير والتحصيلات وإشعارات الائتمان ورديات العملاء إلى عملة ذمة الفاتورة المثبتة.
- موصلات فواتير الشراء ومدفوعات الموردين والمردودات والاستردادات إلى عملة فاتورة الشراء المثبتة.
- موصل الحسابات النقدية والبنوك والمحافظ إلى الربط الفريد غير القابل لتغيير العملة في `financial_accounts`.
- استخدام أدلة سطور الأرصدة الافتتاحية المتحققة مسبقاً بدلاً من التخمين من القيد المجمع.
- رفض مغلق للمصدر المفقود أو الأجنبي أو المكرر، والقيد اليدوي النقدي غير المدعوم، وربط الحساب النقدي الغائب/المكرر.
- تجاهل القيود اللاحقة لتاريخ الإقفال دون قراءة أرصدة حالية مخزنة.

## الاختبارات المنفذة محلياً

- `npm run lint:core`: ناجح.
- اختبارات C3 المركزة: 15/15 ناجحة.
- `npm test`: 276/276 ناجحة.

هذه نتائج هندسية محلية فقط. لا تُعد قبولاً على Render ولا إذناً بالترحيل. CI الكامل (Emulator/UI/audit) مطلوب للكود المرفوع.

## المخاطر والحدود

- لا يوجد أمر ترحيل لإعادة التقييم ولا واجهة مستخدم حتى الآن.
- القيود اليدوية على الذمم ترفض عمداً لأنها لا تحمل مصدر عملة غير قابل للالتباس؛ يلزم مسار تسوية/اعتماد مستقل قبل دعمها.
- قبول Render مؤجل حتى وجود نشر staging مطابق للـcommit مع مؤسسة وبيانات اصطناعية قابلة للمصادقة.
