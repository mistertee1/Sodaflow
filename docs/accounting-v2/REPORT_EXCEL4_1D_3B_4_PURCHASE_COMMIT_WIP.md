# Excel4.1d.3b.4 — تنفيذ جزئي وعائق مطابقة ضريبة الشراء

التاريخ: 2026-10-21. هذه **مسودة غير مكتملة** فوق PR #112، ولا تثبت الجاهزية التجارية.

## المنفذ والمختبر محلياً

- إنشاء فواتير المورد التاريخية والسداد والاستلام وقيود AP/المخزون وFX من الأدلة المراجعة.
- تحديث المورد والمنتج وحجز رقم المورد والجلسة والتدقيق داخل معاملة واحدة.
- إعادة حساب بصمات staging قبل التخطيط، واشتراط baseline صفري ومطابقة الحالة المقترحة قبل الالتزام.
- إعادة طلب العملية تعيد النتيجة نفسها؛ حجز مرجع المورد أو استلام سابق لآخر تكلفة يرفضان بلا كتابة جزئية.
- إعادة اقتباس ضريبة المشتريات من الإصدار التاريخي المحفوظ وإثبات سلسلة إصداراته داخل المعاملة.
- منع خلط فواتير البيع والشراء في جلسة واحدة حتى يتوفر replay موحد لتسلسل تكلفة المخزون، ومنع أبعاد المستندات غير المرحّلة.

## العائق المثبت

المسار الأساسي الحالي في `returnSources.ts/buildPurchaseReturnBases` يفترض أن مجموع تكلفة المخزون يساوي كامل إجمالي فاتورة الشراء، ويقبل حسابي 1300 وAP/النقد فقط. كما أن `purchaseCorrections.ts/verifyPurchaseSource` يصنف حسابات المصدر دون حساب الضريبة المستردة. لذلك لا يستطيع إثبات فاتورة ذات ضريبة مشتريات منفصلة.

اختبار فاتورة صافيها 100 وضريبتها المستردة 15 ينجح في إعادة الاقتباس ثم يرفض في المطابقة الشاملة، مع إثبات بقاء حالة المتجر كاملة دون تغيير. لم يُحذف `source_event_sequence` ولم تُعطل مطابقة التصحيحات لتمرير الفاتورة. الشراء غير الخاضع للضريبة نجح ذرياً، أما الخاضع فيظل fail-closed.

يلزم استكمال مصدر المردود/الاسترداد الضريبي وإثبات توزيع الضريبة والبنود والقيود التاريخية بعد تغيير السياسة، ثم اختبارات USD/FX والبنود المكررة والنسخ الاحتياطي والتزام الفشل، قبل اعتبار Excel4.1d.3b.4 منجزة. يجب مراجعة العمل المقابل في مسار الضرائب السابق وعدم نسخ ملفات كاملة فوقه.

## التحقق

- `npm run check`: ناجح، يشمل TypeScript وcore rules و71 اختبار Excel/import و373 وحدة/API والبناء.
- 3 اختبارات جديدة: حفظ غير خاضع وإعادة الطلب، rollback للحجز/التسلسل، ورفض ضريبة منفصلة دون حالة جزئية.
- لم تُنفذ اختبارات Emulator أو Playwright محلياً لهذا التنفيذ؛ نتيجة CI مستقلة ولا تُفترض.
- لم يحدث دمج إلى main أو نشر أو تغيير قواعد Firebase أو بيانات إنتاج. تحديث Netlify/المزامنة في PR #113 خارج هذا النطاق.

تبقى نقطة الاستئناف Excel4.1d.3b.4؛ هذه المسودة ليست مرحلة مكتملة ولا يوصى بدمجها بوصفها قبولاً نهائياً.
