# التالي: Excel4.1e.3 — حزمة الترحيل من النظام السابق

هذه خطة استئناف وليست تنفيذاً مقبولاً للحزمة. بعد قبول واجهة الجداول، ابدأ من أحدث main وPR وفرع ونقطة تقدم، ولا تنسخ مسودات الفروع القديمة. PRD يذكر Legacy Migration Package ضمن Phase4، ويحدد ترتيب onboarding في175 وبوابة المطابقة في176؛ يجب إثباتهما، لا الاكتفاء باسم ملف جديد.

## إعادة استخدام العقود المقبولة

- قوالب البيانات الرئيسية: src/services/masterImportWorkbook.ts وحقول وصلاحيات masterImport.ts؛ العملاء ثم الموردون ثم المنتجات.
- قالب الأرصدة الافتتاحية بأوراقه الست: openingImportWorkbook.ts؛ المخزون ثم AR ثم AP ثم النقد والبنوك ثم رأس المال، عبر openingPreview والاعتماد الأصلي والمطابقة. لا افتتاحية افتراضية أو تحويل صامت لدفتر آخر.
- الأدلة التاريخية: historicalImportWorkbook.ts وHistoricalWorkbookCenter؛ المبيعات والمشتريات في ملفين وجلسـتين منفصلتين، مع staging ومعاينة حديثة وبصمات واعتماد صريح وإيصال قابل للاسترداد. لا تخمين COGS أو ضريبة أو FX ولا إحياء مسار legacy غير المراجع.
- المصادر والقيود والذمم والمخزون لا تُستبدل من ZIP أو من المتصفح. أي ترحيل يمر بالأوامر الأصلية والصلاحيات والفترة والتدقيق والمطابقة وحدود الكتابة المقبولة.

## أقرب نتيجة قابلة للمراجعة

1. حزمة تنزيل محدودة تجمع القوالب الرسمية المستقلة ودليل ترتيب المراحل وmanifest بإصداراتها وحدودها وSHA256 لبايتات كل ملف. تبقى الملفات متوافقة مع parsers الأصلية؛ لا دمج أوراق في مصنف لا تقبله تلك parsers. بناء ZIP لا يمنح استيراد ZIP خارجي أو فك ضغطه تلقائياً.
2. أي مراجع حية مضمنة تحتاج إثبات صلاحيات التصدير/الاستيراد الحالية بحسب الوحدة، وwhitelist بلا اتصال/credentials أو صور تدقيق خام. لا تنقل صلاحيات نوع ملف إلى آخر لمجرد تجميعه في حزمة. تراجع حدود الحجم والسجلات قبل البناء، ويسجل تصدير حساس خادمياً ببصمة البايتات، دون الثقة بـhash يعلنه العميل.
3. واجهة إرشاد تربط المراحل الموجودة وتعرض نتيجة Gate176 الحالية: TB balanced وAR/AP/Inventory reconciled وOpening Equity validated. أخطاء القراءة/الـhash/الأدلة نتائج غير مقبولة، وليست صفراً. تربط النتيجة بالمؤسسة والمستخدم والمراجعة ووقت/بصمة الحالة، وتصبح قديمة عند التغيير. لا تكتب علامة جاهزية تجارية ولا ترحّل تلقائياً.
4. اختبارات للعقود الأصلية وبايتات القوالب والـmanifest والعزل والحدود ورفض الخلايا/الأدلة غير الآمنة، ثم API/Emulator/واجهة حقيقية عبر الأوامر القائمة. تشمل فشل الترحيل بلا حالة مالية جزئية وإعادة المحاولة والاسترداد والمطابقة بعد الاعتماد. يمنع Ready to Start عند أي finding دون تخفيف assertions.

يُختار نطاق الحزمة بالتفصيل من العقود الحالية قبل كتابة مصدرها؛ لا توجد متطلبات مالية مخترعة من عنوان Phase4 وحده. لا إعادة بناء لمحاسبة المشتريات أو قواعد التزامن أو Super Admin أو شاشات العملات. لا دمج main أو نشر أو Rules/claims أو مؤسسات/أموال إنتاجية. قبول الفهارس وIAM والموفر الخاص والتشغيل الدوري والنسخ والاستعادة المصادق عليه يبقى منفصلاً ولا يستنتج من نجاح مصدر الحزمة.
