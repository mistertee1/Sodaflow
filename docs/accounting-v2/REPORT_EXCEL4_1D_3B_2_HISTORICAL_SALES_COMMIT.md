# تقرير Excel4.1d.3b.2 — الاعتماد الذري للمبيعات التاريخية

## النتيجة

اكتمل ربط خطة المبيعات التاريخية بمعاملة الاعتماد الأصلية. تستطيع الجلسة المراجعة الآن إنشاء فاتورة بيع وتحصيلاتها وحركة المخزون وقيودها وتحديث أرصدة العميل والمنتج معاً، ولا تحفظ أي جزء إذا لم تعد الحالة الناتجة متطابقة صفراً.

## المنفذ

- إنشاء فواتير V2 أصلية من بنود الدليل المثبت، مع AR والإيراد والضريبة وCOGS ولقطات تكلفة البنود.
- إنشاء سندات التحصيل وفق أسعار الصرف التاريخية وتسلسل المصدر، مع إثبات فروق العملة في القيود.
- تجميع البنود المتكررة للمنتج في حركة بيع واحدة قابلة لإعادة التحقق، وتحديث كمية وقيمة ومتوسط تكلفة المخزون.
- تحديث رصيد العميل من الذمم الناتجة، وحجز رقم الفاتورة، وتحديث العدادات والجلسة وسجل التدقيق.
- التحقق من سلسلة إصدار الضريبة المجمدة وإعادة اشتقاق قيمها وحسابها قبل الحفظ.
- مطابقة baseline قبل التخطيط ومطابقة الحالة المقترحة بعده؛ أي فرق في المبيعات التاريخية يؤدي إلى rollback كامل.
- منع حسابات التحصيل غير النظامية، وحساب إيراد غير 4100، وتصنيفات الحسابات غير المتوافقة، والتكلفة التي تتجاوز قيمة المخزون.

## التحقق المحلي

- 61/61 اختبار Excel/import ناجح، منها اعتماد ذري، idempotency، rollback، ضريبة تاريخية، وتجميع بنود المنتج.
- 373/373 اختبار وحدة/API ناجح.
- TypeScript وcore rules والبناء ناجحة.
- `npm audit --omit=dev`: صفر ثغرات إنتاجية.
- تعذر تشغيل Firestore Emulator محلياً لأن صورة التنفيذ تحتوي Java أقدم من 21.
- تعذر تشغيل Playwright محلياً لعدم وجود Chromium في صورة التنفيذ؛ تبقى بوابتا Emulator وUI مطلوبتين من CI.

## الحدود والباقي

- مشتريات AP التاريخية ما زالت مرفوضة قبل أي كتابة؛ المرحلة التالية تنشئ خطة الشراء والاستلام والتكلفة المتوسطة ثم تربطها بالاعتماد.
- قبول Render المصادق عليه مستقل وما زال معلقاً على commit staging مطابق.
- لم يحدث دمج أو نشر أو تعديل على `main` أو قواعد Firebase أو بيانات إنتاج.
