# تقرير Excel2.1 — حزمة المحاسب والتصدير المتطابق

## النتيجة

نُفّذت مرحلة Excel2.1 على الفرع `codex/accounting-v2-excel2-accountant-export-20261016` المبني على فرع Excel1.2، وفتح PR #89. لا يوجد دمج أو نشر أو migration.

## المنفذ

- مصنف Excel XML محدد الفترة يحتوي القيود والسطور وميزان المراجعة وقائمة الدخل والميزانية والتدفق النقدي.
- أرقام SDG وUSD في خلايا رقمية مستقلة، مع مراجع المصدر وأبعاد الفرع ومركز التكلفة والمشروع.
- ورقة مطابقة تجمع أدلة البنك والنقد، وورقتا Data Dictionary وExport Summary بإصدار schema والفترة والأعداد.
- أمر `accountingExport.create` محمي للمالك والمدير والمحاسب فقط، ويتطلب صلاحية دفتر اليومية والتقارير المتقدمة وAccounting V2 والاشتراك المناسب.
- عزل مستأجر، idempotency، وحدود 5000 قيد و900KB، وسجل `DATA_EXPORT_CREATED` للفترة والأعداد.
- واجهة لتنزيل دفتر المحاسب لفترة اختيارية، مع إخفائها عن Viewer والتحقق من الفترة المعكوسة.

## التحقق

- 3 اختبارات Excel2.1 للسلامة الرقمية والصلاحيات وعزل المستأجر والحجم وidempotency والتدقيق: ناجحة محلياً.
- 370 اختبار وحدة/API regression: ناجحة محلياً.
- TypeScript و`lint:core` والبناء: ناجحة محلياً.
- أضيف اختبارا Playwright لصلاحية المحاسب والتنزيل والأوراق والتدقيق بعد إعادة التحميل وحجب Viewer. تعذر تشغيلهما محلياً لغياب Chromium؛ نتيجة CI هي الدليل المطلوب لهما.
- GitHub Actions run `38870018149` على الالتزام `cf5c8cc5efcd2c1863857f3df2afd7ee19165ef4`: ناجح.
- 3/3 اختبارات Excel2.1 و370/370 وحدة/API و35/35 Firestore Emulator و87/87 Playwright: ناجحة.
- `npm audit --omit=dev`: صفر ثغرات production.

## الحدود والباقي

- الحد المباشر 5000 قيد و900KB؛ jobs الكبيرة والملفات المؤقتة والفشل/الاستئناف ضمن Excel3.2.
- لا تشمل المرحلة saved presets أو full-company portability أو auditor package أو import مالي؛ هذه ضمن Excel2.2–Excel4.
- قبول Render المصادق عليه مستقل ومعلق حتى توفر staging مطابق للالتزام ومساحة عمل معتمدة؛ لم يحدث نشر أو اختبار ببيانات عملاء.
- نقطة الاستئناف التالية بعد نجاح CI هي Excel2.2: استيراد افتتاحي مالي آمن يمر عبر المصادر والقيود والمطابقة.
