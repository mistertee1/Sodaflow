# تقرير C1.2 — واجهة الفترات ومساعد إقفال الشهر

تاريخ التقرير: 2026-10-07. الفرع `codex/accounting-v2-c1-period-ui` تابع لـ C1.1؛ لا يدمج المستخدم الأساس تلقائياً. **CI ناجح: 191 وحدة/API و26 Firestore و44 واجهة وصفر ثغرات إنتاج. الأنواع والبناء والفحص الصارم ناجحة، و5 اختبارات جديدة للهاتف ضمن التحقق الكامل.**

## التنفيذ

- استبدال شاشة تاريخ الإقفال المفرد بإنشاء واختيار الفترات وحدودها وحالتها وإصدارها، والإقفال المبدئي والنهائي وإعادة الفتح. توضّح الشاشة أثر إنشاء أول فترة على تغطية جميع تواريخ الترحيل، وتحتفظ بالإقفال القديم كحماية إضافية حتى يزيله المالك صراحةً.
- مساعد إقفال الشهر يعرض مطابقة المبيعات والمصروفات المسجلة، الصندوق والبنك والمحافظ، المخزون والتكلفة، AR/AP، اتزان العملتين واكتمال القيود المصدرية. الملخصات محسوبة من **كل** الملاحظات الخادمية، ولا تعتمد على أول 100 نتيجة المعروضة. تظهر الحسابات التي تحتاج مطابقة حتى نهاية الفترة، وعدد جميع الملاحظات ومراجع مصادرها. لا يظهر زر الاعتماد مفعلاً قبل نجاح الفحص وتأكيد مراجعة الصرف، ويعيد الخادم الفحص داخل معاملة الإغلاق.
- الدليل النهائي يعرض المراجع والوقت والسبب وبصمة دفتر العملتين وعدد مصادر المطابقة. إعادة الفتح تعرض الفاعل والتاريخ والسبب وتحتفظ بالحالة السابقة وسجل التدقيق.
- قيد اليوميات اليدوي يدعم تسوية صريحة مع سبب للمحاسب/المالك. الخطأ يحفظ المدخلات، والضغط المزدوج لا يكرر القيد أو انتقال الفترة. الحسابات Admin/Viewer لا ترى إدارة الفترات أو قيد التسوية، ولا يرى المحاسب إعادة فتح المالك.
- نافذة تحقق المالك تستخدم الحساب الحالي المرتبط بالبريد وكلمة المرور أو Google عبر `reauthenticateWithCredential` / `reauthenticateWithPopup`، ثم تحدّث ID token. لا تضيف الهاتف أو طرق دخول جديدة، ولا تحفظ كلمة المرور أو ترسل auth_time من الواجهة. تتحقق من بقاء UID والمؤسسة والجلسة قبل/بعد التحقق وقبل العملية؛ الخادم يظل مصدر الصلاحية والتحقق الحديث. إخفاق المزود أو تبديل الحساب يمنع العملية.
- إزالة الإقفال القديم تستخدم نفس التحقق والسبب، ولا تفتح فترة مقفلة في النظام الجديد. التأكيد التجريبي ظاهر بوضوح **محلي فقط**، ولا ينتقل إلى النقل السحابي أو يمنح أي صلاحية سحابية.

## التحقق

- `npm run check`: 191 وحدة/API ناجحة، مع 4 حالات جديدة فوق C1.1: ملاحظة مورد بعد حد العرض، محفظة بلا مطابقة، ترتيب إثبات الهوية قبل تحديث التوكن ورفض الهوية غير الموثقة/غير المرتبطة، ومنع العملية عند فشل التحقق أو تغير UID أثناءه أو أثناء تحديث التوكن. الأنواع والفحص الصارم والبناء ناجحة؛ الأنواع والبناء أعيدا بعد التعديلات الأخيرة للواجهة.
- 5 Playwright جديدة ناجحة عند عرض 390×844: دورة OPEN→SOFT_CLOSED→CLOSED→REOPENED، منع القيد العادي وقبول تسوية مسببة ثم منعها في CLOSED، مراجعة الصرف، تدقيق الحالة السابقة/الجديدة، عدم التكرار، حفظ الحالة والسبب بعد Reload؛ فرق الجرد الفعلي يمنع الإغلاق؛ وصلاحيات Accountant/Admin/Viewer. اجتاز عدم التمدد الأفقي وراجعت صور شاشة الحالات.
- [CI الحالي](https://github.com/mistertee1/Sodaflow/actions/runs/37687099864) على `00962a6c9d8934ea1875d75b2677804b41ee7e0f`: 191 وحدة/API، و26 Firestore، و44 واجهة وصفر ثغرات إنتاج.
- الأساس C1.1 موثق على `5c64692a208dcfd191f0908d083d7f05c5e547da`: 187 وحدة/API و26 Firestore و39 واجهة وصفر ثغرات إنتاج في [CI](https://github.com/mistertee1/Sodaflow/actions/runs/37685870678). لا تعتبر هذه الأعداد إثباتاً لـ CI الفرع الجديد حتى يكتمل تشغيله.

## الحدود والمتبقي

الفحص محافظ ويشمل اتساق المؤسسة كاملة وأحدث دليل مطابق لكل حساب نقدي تحرك حتى نهاية الفترة. مراجعة FX إقرار يدوي موثق، وإعادة التقييم الآلية في مرحلة C اللاحقة. لا تُخترع عمليات غير مسجلة أو تكاليف تاريخية مجهولة. الحدود الخادمية للإغلاق والنسخ السابقة باقية.

C1 مُنفذ وCI ناجح؛ C ككل لم يكتمل. التالي C2: مساعد الأرصدة الافتتاحية ورأس مال المالك والمسحوبات مع مصدر وتدقيق وتحقيق حديث، ثم بقية FX/الأصول/الضرائب/المقارنات والإثباتات، ثم D/E وExcel1–4 ومتطلب استيراد كشوف البنك PRD50.

حافظنا على Super Admin وتحقق التوكن ونقل المزامنة وإعادة المحاولة. إضافات AppContext تقتصر على قراءة/أوامر الفترات وتحديد المؤسسة والتسوية والتحقق؛ لم نستبدل مسار المزامنة. لم يحدث دمج أو كتابة إلى main أو نشر تطبيق/Rules أو تعديل بيانات إنتاج. main ما زال عند `1f2d5b238ed0c0f46a2328768b0b5659719efa31`؛ آخر مشتريات B3 ومستنداتها اندمجت بين الفروع التابعة بعد دمج PR20، لذا على المستخدم دمج الأساس النهائي عند المراجعة.

مراجع التنفيذ: [Firebase إعادة التحقق](https://firebase.google.com/docs/auth/web/manage-users#re-authenticate_a_user)، [مرجع Auth](https://firebase.google.com/docs/reference/js/auth#reauthenticatewithpopup). الجاهزية التجارية والشروط 94–98 غير مكتملة.
