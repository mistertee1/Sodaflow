# Excel4.1e.1 — قالب وقارئ أدلة الاستيراد التاريخي

التاريخ: 2026-10-21. فرع تابع لـPR #114؛ المستخدم وحده يراجع ويدمج.

## المنفذ

- قالب XLSX فعلي بخمس أوراق: Instructions وExamples وDocuments وLines وPayments، مع عناوين ثابتة وصف علوي ثابت وفلاتر وأعمدة رقمية.
- ربط المستندات بالبنود والدفعات بأرقام صريحة، مع الحفاظ على COGS وقيمة المخزون والضريبة وبصمة إصدارها وسعر صرف الفاتورة وكل دفعة مستقلاً.
- قارئ ينتج طلب staging وبصمة SHA-256 للملف ونتيجة تحقق محلية؛ لا ينشئ جلسة أو فاتورة أو دفعة أو قيداً ولا يغير المخزون.
- رفض الصيغ ذات النتائج المحسوبة، الخلايا المدمجة، الأوراق الزائدة أو المالية المخفية، العناوين المعدلة، أرقام الأموال النصية، التواريخ غير الصريحة، المراجع اليتيمة والتسلسلات المكررة أو الناقصة، والملفات المختلطة بيعاً وشراءً.
- تطبيق عقود التاريخ والفترة والحسابات والطرف والبنود والضريبة والسداد الحالية، دون اختلاق تكلفة أو سعر صرف أو ضريبة تاريخية. الخادم يظل مصدر الصلاحية ويعيد التحقق عند staging والاعتماد.

## التحقق

- 6 اختبارات XLSX فعلية جديدة: round-trip بيع، شراء USD بضريبة وإصدار محفوظ وأسعار صرف مستقلة، الصيغ/الدمج/العناوين/الأوراق، روابط وتسلسلات مكسورة، دقة الأموال والتواريخ والفترات المقفلة، والملفات الفارغة/الزائدة/المختلطة/الأطراف المجهولة.
- النتيجة النهائية لـCI والفحص الكامل تسجل في PROGRESS.json عند الإغلاق، ولا تُفترض قبل نجاحها.

## الحدود والباقي

- هذه خطوة عقد مصنف وقارئ فقط. لا يوجد زر واجهة أو تأكيد اعتماد جديد في هذا PR؛ الربط والمعاينة والخادم والاعتماد هي Excel4.1e.2 التالية.
- الحد 2MB و200 مستند و100 بند/دفعة للمستند. حدود حجم staging و400 كتابة مالية مفروضة أيضاً في مسار الخادم وقد تحتاج تقسيم الملف.
- التواريخ نص YYYY-MM-DD والأموال أرقام Excel ثابتة. لا يدعم هذا القالب القيود وميزان المراجعة؛ عقودهما الخلفية موجودة وتحتاج مسار واجهة الترحيل المناسب.
- حزمة الترحيل وحزمة المدقق والتصدير المجدول وقبول Render ومراجعة شروط الوثيقة كاملة ما زالت مطلوبة. لا جاهزية تجارية شاملة.
- لا دمج إلى main أو نشر أو تعديل Firebase Rules أو بيانات إنتاج، ولا تعديل على Super Admin أو المزامنة.
