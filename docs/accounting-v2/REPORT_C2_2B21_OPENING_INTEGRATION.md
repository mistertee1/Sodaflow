# تقرير C2.2b.2.1 — ربط الافتتاح بالتقارير والمطابقة والاستعادة

تاريخ التقرير: 2026-10-08 UTC. الفرع `codex/accounting-v2-c2-opening-integration` تابع لـ[PR27](https://github.com/mistertee1/Sodaflow/pull/27). **هذا ربط مصادر مالية محفوظة، وليس أمر بدء الأرصدة أو واجهة المساعد.**

## ما تغير

- كشوف AR/AP وأعمار الذمم تربط كل lot افتتاحي بسطره المحدد في القيد؛ قيد واحد لعدة عملاء/موردين لا يوزع كله على طرف واحد. التسويات تُرتب بتاريخها وتسلسلها، وتُفحص الأحداث اللاحقة حتى عند طلب تقرير قديم. تواريخ الاستحقاق الافتتاحية القديمة تبقى صريحة.
- المراجع تحمل `source_type/source_id/source_reference` و`opening_lot_id` مع journal/line references. حقول invoice_id/bill_id تبقى فارغة عند مصدر افتتاحي؛ لم تُنشأ فواتير شراء أو بيع وهمية. تظهر عبارة «رصيد افتتاحي» على الهاتف، وتحتفظ صادرات CSV/PDF بمراجع الدفعة والlot والتسوية.
- تحديث customer/supplier caches عند إنشاء فاتورة/شراء/قبض أو تصحيح/مردود يحفظ الأرصدة الافتتاحية التاريخية بجانب مصادر الفواتير؛ تجمع Due منفصلة عن Credit/Advance. الرصيد الظاهر لا يمحو الافتتاح. حذف عميل مرتبط بمصدر افتتاحي يُمنع حتى بعد تمام التسوية.
- مجموعات `opening_batches/opening_lots/opening_settlements` أضيفت إلى FinancialData والتدقيق المحاسبي وchecklist الإقفال والقراءات المحمية والنسخ. المصدر يثبت AR/AP↔GL وInventory↔GL بالعملتين؛ القيد اليدوي غير المخصص يبقى فرقاً صريحاً.
- النسخة تحمل `opening_schema_version=1` وعدّادات مشتقة من عدد المستندات الفعلي. الاستعادة ترفض مجموعات ناقصة أو counts مختلفة أو مصدر افتتاحي بلا إثبات أو مؤسسة أصلية مختلفة، وتفحص الأصل قبل التطبيع. ثم تطبع snapshot وquote وaccount_basis وfinancial_basis والمؤسسة الخارجية إلى الوجهة، وتعاد المطابقة دون فروقات قبل كتابة أي سجل. المالك الجديد لا يتغير، وتبقى هوية المنشئ الأصلي وأرشيف التدقيق.
- النسخ القديمة الخالية فعلاً من أدلة افتتاح تظل متوافقة. حدود الاستعادة الذرية 350 سجلاً و440 سجلاً مع الفهارس وحد الخادم 450 كتابة لم تُوسّع. فحص المصادر الحالي محدود بـ1200 مستند لكل مجموعة و200 تسوية لكل lot؛ التاريخ الأكبر يحتاج مساراً خادمياً مضبوطاً.
- فُصلت أسماء مجموعات الافتتاح في module مستقل لإزالة اعتماد دائري ظهر عند تشغيل مجموعة الاختبارات كاملة. يجري إثبات AP مرة واحدة لكل فحص، ثم تجمع الأطراف من النتيجة نفسها.

## التحقق

نجح محلياً `npm run check`: **227 اختبار وحدة/API**، مع فحص الأنواع والفحص الصارم والبناء. أضيفت 8 حالات تغطي عدة أطراف في قيد واحد، القيود اليدوية غير المخصصة، تسويات بفرق صرف، العبث المستقبلي مع تقرير قديم، فاتورة وشراء وقبض بعد الافتتاح، تصحيح سعر ومردود شراء بالقيمة الأصلية وWAC، counts والمصادر والمؤسسة الأصلية، تطبيع متداخل، استعادة مرتين، وبقاء مراجع العميل بعد الإقفال الصفري.

أضيف اختبار Firestore حقيقي داخل `demo-sudaflow` فقط: بيع بعد إثبات الاختبار، نسخة محمية، رفض نسخة ناقصة دون كتابة جزئية، استعادة إلى مؤسستين، مطابقة 20000 SDG / 11 USD في AR و3000 SDG / 2 USD في AP، وبقاء منع SDK. وأضيف اختبار هاتف لعرض المراجع الافتتاحية وتصدير AR/AP دون فواتير وهمية أو تجاوز عرض الشاشة. **نتيجة emulator والواجهة تنتظر CI**؛ البيئة المحلية Java17 ولا تحتوي متصفح Playwright، فلا يُنسب لهما نجاح محلي. إثبات الدفعة والتسويات في fixtures بيانات اختبار، ولا يمثل أمر افتتاح متاحاً للمستخدم.

## التالي والحدود

C2.2b.2.2 أوامر الافتتاح والتسوية الذرية: مالك فعلي وتحقق حديث، معاينة حديثة وسبب وميزات حالية، فترات وصلاحيات قبل cached retries، منع collisions/races، تحقق رصيد الصرف والتواريخ اللاحقة، overlay ثم مطابقة قبل commit، التدقيق والعدادات، واختبارات Firestore ذرية. بعدها C2.2b.3 المساعد والتسويات وC2.3 رأس المال والمسحوبات، ثم C3–C6 وD/E وExcel1–4 ومتطلبات القبول النهائي.
