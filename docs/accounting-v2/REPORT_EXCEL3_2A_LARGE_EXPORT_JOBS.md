# تقرير Excel3.2a — أساس مهام التصدير الكبيرة

## النتيجة

أضيف مسار خادمي محمي لطلب مهام تصدير كبيرة وإلغائها وإعادة محاولة الفاشل منها. المرحلة لا تشغّل عاملاً خلفياً ولا تنشئ ملفاً أو رابط تنزيل؛ هذان جزء Excel3.2b التالي.

## ما نُفذ

- طلب مهمة شركة بصيغة JSON للمالك الفعلي فقط، أو مهمة دفتر محاسب بصيغة XLSX لمن يملك صلاحية التصدير المحاسبي.
- فترة اختيارية وإعداد محفوظ متطابق لمهمة المحاسب، مع إعادة التحقق من V2 والاشتراك وميزة التقارير المتقدمة.
- حد تشغيلي قدره ثلاث مهام queued/running للمؤسسة، وثلاث محاولات كحد أقصى.
- إلغاء المهمة النشطة وإعادة محاولة المهمة الفاشلة لمنشئها أو المالك، مع تصفير التقدم وإزالة أي artifact أو expiry قديم قبل المحاولة الجديدة.
- فصل `company_export_jobs` المحمي بـ`export:company` عن `accounting_export_jobs` المحمي بـ`export:accounting` حتى لا يكشف snapshot المحاسب بيانات مهام الشركة.
- أحداث تدقيق `DATA_EXPORT_QUEUED` و`DATA_EXPORT_CANCELLED` و`DATA_EXPORT_RETRIED` وهوية عملية idempotent.

## الاختبارات

- اختبار المالك والمحاسب والعزل بين مجموعتي القراءة.
- رفض المشاهد، والمحاسب الذي يطلب حزمة شركة، والحقول المحمية، والفترة المعكوسة، وتجاوز حد المهام.
- الإلغاء وإعادة المحاولة وحد المحاولات وعدم تسرب artifact/expiry.
- regression لحزمة Excel3.1، وlint/build/audit الكامل محلياً.
- تحقق CI النهائي موثق في `PROGRESS.json` وطلب المراجعة #95.

## المخاطر وما بقي

- لا يوجد worker أو توليد artifact أو توقيع/انتهاء رابط أو تنظيف تخزين في هذه المرحلة؛ لا يجوز اعتبار المهمة queued ملفاً جاهزاً.
- لا توجد مهام استيراد كبيرة أو واجهة تقدم/تنزيل بعد؛ تنتقل إلى Excel3.2b/Excel3.2c.
- لم يحدث نشر أو migration أو كتابة معاملات إنتاجية. قبول Render المصادق عليه مستقل ومعلق إلى أن تتوفر نسخة staging مطابقة للالتزام وسيناريو مستخدم اصطناعي مخول.
