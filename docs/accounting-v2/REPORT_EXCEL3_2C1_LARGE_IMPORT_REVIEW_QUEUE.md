# تقرير Excel3.2c.1 — مراجعة وجدولة الاستيراد الكبير

## النتيجة

اكتملت طبقة مراجعة وجدولة الاستيراد الكبير على فرع `codex/accounting-v2-excel3-large-import-ui-20261018` المتراكم فوق PR #96. تضيف المرحلة أوامر محمية لطلب المهمة وإلغائها وإعادة محاولتها، وواجهة مراجعة صريحة، وعزل الصلاحيات والمستأجر، من دون اعتماد السجلات التجارية أو تنفيذ worker أو كتابة بيانات مالية.

## ما نُفّذ

- لا يُقبل الطلب إلا لجلسة staging موجودة ومعاينة مطابقة، وبإقرار `reviewed: true` وسياسة تكرار صريحة `skip|update`.
- يمنع الخادم الأخطاء المانعة، وعدم تطابق عدد الصفوف، والملفات خارج حد 1–12000 صف، ويحتفظ ببصمة الملف وإصدار المخطط ودليل المراجعة.
- تربط idempotency كامل دليل الطلب ببصمة الملف والمخطط والجلسة وسياسة التكرار، فترفض إعادة استعمال المفتاح لمحتوى مختلف.
- حد أقصى مهمتان نشطتان للمؤسسة وثلاث محاولات للمهمة، مع أوامر إلغاء وإعادة محاولة idempotent ومؤشر خاص في `large_import_queue`.
- يعاد فحص عضوية المؤسسة واشتراك المحاسبة وصلاحية الاستيراد الخاصة بالوحدة؛ لا يرى Viewer مهام الاستيراد في snapshot.
- تعرض الواجهة سياسة التكرار، وتحذيراً واضحاً بأن الجدولة لا تعتمد السجلات، والتقدم والحالة والإلغاء وإعادة المحاولة مع بقاء الحالة بعد إعادة التحميل.
- تسجل دورة الطلب أحداث `DATA_IMPORT_QUEUED` و`DATA_IMPORT_CANCELLED` و`DATA_IMPORT_RETRIED`.

## الحدود والمخاطر المتبقية

- هذه المرحلة لا تشغّل worker ولا تكتب في `customers` أو `suppliers` أو `products` ولا تعتمد قيوداً أو بيانات مالية.
- Excel3.2c.2 يجب أن يضيف القراءة المتقطعة من staging، والتحقق قبل الاعتماد، وحالة `awaiting_commit`، والاعتماد الذري، والتراجع/undo وقواعد rollback.
- قبول Render منفصل ومعلق حتى تكون نسخة staging المصادق عليها مطابقة للالتزام؛ لم يحدث نشر أو دمج أو migration أو كتابة إنتاجية.
