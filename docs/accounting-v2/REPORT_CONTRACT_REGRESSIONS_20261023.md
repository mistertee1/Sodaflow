# استعادة عقود الائتمان وتدقيق Excel بعد دمج الفروع

2026-10-23 — فرع تابع لـPR137؛ المستخدم وحده يراجع ويدمج.

## المشكلة المثبتة

كان الفحص المعتاد يمرر455 وحدة/API، لكنه لم يشغّل24 ملف اختبار للوحدات المحاسبية الأحدث. كشف تشغيلها107 اختبارات إضافية و11 فشلاً: حدود ائتمان العميل لا تُحفظ رغم وجود حارس الصلاحية، وأحداث تدقيق تصدير/استيراد Excel فقدت تصنيف الحدث وبياناته، ورسالة تجاوز حد التصدير لا تعرض5000. نجاح CI القديم وحده لم يكن دليلاً على اكتمال الوثيقة.

## الإصلاح

أُعيد حفظ credit_limit_sdg وcredit_limit_usd وcredit_policy والتحقق من دقة العملتين والسياسة، مع إبقاء دعم العملات الإقليمية وتطبيع الهاتف وإصلاح الفواتير وحالة Super Admin والمزامنة. تُلتقط تغييرات حد الائتمان في حالة التدقيق المحفوظة أيضاً. اختبارات D4 تثبت رفض الموظف غير المخول، ورفض الائتمان المتجاوز عند اشتراط الموافقة، وتوثيق موافقة المالك، والسياسة التحذيرية، والتراجع الكامل عن الدقة أو السياسة غير الصالحة.

أُعيدت12 خريطة أحداث من مصدر Accounting V2 الأحدث، بعد مقارنة الفرق، دون استبدال ملف operations: التصدير السريع والمحاسبي والشامل، وطلب/إلغاء/إعادة محاولة التصدير الكبير، ومعاينة استيراد البيانات الرئيسية، وطلب/إلغاء/إعادة محاولة/اعتماد/تراجع الاستيراد الكبير. تحفظ الأحداث نوع العملية والإصدار والمجموعة والأعداد والفترة والحقول المحجوبة أو مرجع النسخة ودليل إعادة المصادقة بحسب العملية. أحداث الاستيراد التاريخي وإصلاحاته في الأساس باقية.

تعرض رسالة تجاوز التصدير الحد الفعلي، مع الإبقاء على حد5000 للطلب المباشر والحد المخصص للمهمة. لا تُرفع الحدود ولا تُخفف الصلاحيات.

أصبح npm test يكتشف ملفات وحدة/API في جذر tests تلقائياً بواسطة scripts/run-unit-tests.mjs؛ اختبارات Firestore المنفصلة تبقى ضمن test:emulator. يمنع ذلك إسقاط اختبارات مرحلة جديدة من قائمة يدوية بعد الدمج.

## التحقق والحدود

نجح npm run check محلياً:562 وحدة/API، و16 Netlify runtime، وTypeScript/core والبناء؛11 فشلاً في الأساس أصبحت ناجحة دون تخفيف assertions الأصلية. أضيف التحقق من دليل تدقيق حدود الائتمان ومن عدم ترك كتابة جزئية بعد رفض الدقة أو السياسة.

الأساس e0673c1c12ada6e15459f45d9fb6b1520a74d636 يتضمن تحسين المخزون وإصلاح اعتماديات body-parser في PR137. تدقيق الإنتاج بعد الإصلاح سجّل صفر ثغرات. CI الخاص بهذا الإصلاح، بما فيه Firestore و125 سيناريو واجهة، مطلوب قبل اكتمال القبول. لا يُعد الفحص المحلي قبول Firebase حي أو تصريحاً تجارياً.

يبقى إلزام الخادم بعقد مراجعة الاستيراد التاريخي، واسترداد الجلسة والإيصال بعد إعادة تحميل الشاشة، وبقية Excel4 وقبول البيئة المصادق عليه وشروط المطابقة والاستعادة النهائية دون فروقات. لم تُكتب تغييرات إلى main ولم يُدمج PR أو يُنشر تطبيق/قواعد أو تُغيّر بيانات إنتاج أو أموال حقيقية.
