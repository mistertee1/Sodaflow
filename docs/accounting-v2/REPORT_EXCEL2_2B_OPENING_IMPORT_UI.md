# تقرير Excel2.2b — واجهة استيراد الأرصدة الافتتاحية

## النتيجة

ارتبط قالب ومحلل Excel2.2a بمركز الأرصدة الافتتاحية المحمي. رفع الملف يملأ مسودة المراجعة فقط، ثم تمر الأرقام عبر المعاينة الحالية واعتماد المالك الحالي؛ لم يُضف أي مسار كتابة أو ترحيل مالي بديل.

## ما تم

- تنزيل القالب الرسمي ورفع ملف XLSX من شاشة الأرصدة.
- تعبئة النقدية والعملاء والموردين والمخزون ورأس المال وشروط الاستحقاق من الملف.
- عرض اسم الملف وعدد المصادر وبصمة مختصرة قبل المعاينة.
- منع Viewer من اكتشاف مركز المحاسبة أو أداة الاستيراد.
- الإبقاء على `opening.preview` للمعاينة و`opening.commit` بعد إعادة مصادقة المالك للحفظ الذري.
- الحفاظ على حراس المؤسسة والجلسة وبصمة المسودة والمزامنة وإعادة التحميل.

## الاختبارات

- اختبار UI يثبت أن رفع القالب يملأ المسودة ويعرض الدليل ولا يكتب أي سجل قبل المعاينة.
- اختبار UI يثبت أن Viewer لا يستطيع اكتشاف مسار المحاسبة أو أداة الرفع.
- 4 اختبارات parser و8 اختبارات pretest الخاصة بالاستيراد.
- نتائج CI الكاملة موثقة في `PROGRESS.json` على commit الكود.

## المخاطر والمتبقي

- لا تُحفظ نسخة الملف نفسها؛ تحفظ المصادر والقيود الناتجة عبر عقد C2، بينما تعرض البصمة في جلسة المراجعة. أرشفة الملفات ومهام الاستيراد الكبيرة تتبع Excel3.
- قبول Render لم يُدّعَ، ويلزم staging مصادق مطابق للالتزام وبيانات اصطناعية.
- الخطوة التالية Excel2.3 لاستيراد كشف البنك إلى staging والمطابقة اليدوية الآمنة.
