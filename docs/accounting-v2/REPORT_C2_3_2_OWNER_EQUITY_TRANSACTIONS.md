# تقرير C2.3.2 — أوامر رأس المال والمسحوبات المحمية

التاريخ: 2026-10-10. الجزء الخادمي فوق C2.3.1؛ واجهة المستخدم وقبول Render في C2.3.3 غير مكتملين.

## ما تغير
- ownerEquity.create عملية ذرية للمالك الفعلي فقط بصلاحية equity:write وتحقق دخول حديث موثق من token. إعادة التحقق من العضوية والباقة والميزات والفترة والإقفال وحساب النقدية قبل إرجاع retry محفوظ.
- source owner_equity_events ثابت، قيد owner_equity محجوز للترحيل الآلي، تدقيق مع actor/auth_time وquote، idempotency receipt وعدد مصادر المؤسسة وتحديث revision الحساب في المعاملة نفسها. لا تعديل أو حذف مالي للمصدر التاريخي.
- قراءة المصادر الكاملة من الخادم، مطابقة الدفاتر قبل وبعد فوق overlay صريح يناسب Firestore ذي الكتابة المؤجلة، فحص فهرس الحساب والمسار الفعلي ومنع تصادم ID. السحب يتحقق من كلا الدفترين في التاريخ وكل إقفال لاحق، مع القيمة الدفترية وباقي التقريب، والإيداع يلتزم سياسة SDG-only أو سعر مزدوج مثبت. حدود المال بعد الحركة تُفحص أيضاً.
- أدلة مصدر قابلة لإعادة الحساب: input/quote، أساس حسابات مصنف دون أرصدة مخبأة أو بيانات أشخاص، قائمة معرفات القيود السابقة من القراءة الخادمية، وتسلسل مصادر المالك. إعادة الحساب تستخدم القيود الفعلية المرجعية وتتجاهل الأسماء/حالة النشاط المتغيرة اليوم. كشف المصادر الناقصة والقيود اليتيمة أو المختلفة والتسلسل المختلف.
- snapshots والصلاحيات وledger والتقارير والمطابقة وclose checklist والنسخ الاحتياطي تشمل المصادر الجديدة. schema/count صريح يمنع إسقاطها، والاستعادة تعيد ربط org داخل الأدلة وتتحقق من المصدر قبل وبعد التحويل؛ لا تغيير لهوية actor التاريخية.
- لا تغيير Rules أو fingerprints أو نشر؛ لا قراءة/كتابة SDK للـcollection الجديدة. القراءة من API تتبع journal:read وميزة accounting.

## الاختبارات
محلياً npm run check نجح: 260 اختبار وحدة/API (12 جديدة)، الأنواع وcore/hash والبناء. اختبار المصدر يشمل التمويل/السحب والتمويل في cash flow دون expense، الصرف المتزامن والتكرار، الأدوار/المالك المزور والتحقق الحديث، الباقة/الميزات/retry، تواريخ/فترات/ربط الحساب، rollback/فشل التخزين والكتابة المؤجلة، HTTP مصادق، SDG-only وتصفير USD الجزئي، استعادة مرتين وتلاعب المصدر، والعمليات العادية بعد السحب.

أضيف اختباران حقيقيان لـFirebase Emulator demo-sudaflow: race/duplicate/rollback ومنع SDK get/list/write للمالك والأجنبي، ثم استعادة مرتين ورفض إسقاط المصدر. لم ينفذا محلياً: Java 17 مقابل بيئة CI Java 21. CI للفرع مطلوب، ولا يثبت build سلوكاً أو Rules أو إطلاقاً تجارياً.

- القراءة/الدليل حتى 1200 سجل لكل collection، وحجم مصدر حتى 200KB؛ الدفاتر الأكبر تحتاج مسار job مضبوط لاحقاً. قائمة القيود السابقة مصدرها الخادم وليست تصريحاً أو توقيعاً خارجياً للنسخة؛ counts/quotes تكشف عدم الاتساق وليست ضماناً ضد تعديل جميع أدلة النسخة معاً.
