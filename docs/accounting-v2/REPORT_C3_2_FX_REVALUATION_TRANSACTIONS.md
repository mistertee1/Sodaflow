# تقرير C3.2 — ترحيل إعادة تقييم العملة

## النتيجة

أضيف أمر خادمي ذري `fxRevaluation.create` يحوّل المعاينة المراجعة إلى قيد تسوية مصدره محفوظ وقابل لإعادة الإثبات، دون قبول مبالغ مشتقة من العميل.

## الضوابط المنفذة

- المالك والمحاسب فقط عبر صلاحية تسويات الفترات؛ Admin وViewer وبقية الأدوار مرفوضون.
- يتطلب محاسبة V2 وباقة نشطة وميزات accounting وmulti-currency وخدمة خادم موثوقة.
- يقبل تاريخ نهاية فترة مغطاة فقط، ويسمح في الفترة المفتوحة أو المقفلة مبدئياً كقيد adjusting، ويرفض الإغلاق النهائي.
- بصمة SHA-256 للمعاينة إلزامية وتُعاد مقارنة المعاينة داخل المعاملة قبل أي كتابة.
- idempotency ذري، تصادم معرفات المصدر/القيد مرفوض، ولا تعديل تلقائي للبيانات التاريخية.
- سجل مصدر `fx_revaluations` يحفظ المدخل، المعاينة، إثبات عملة كل طرف، الحسابات والفترة والقيود السابقة.
- التحقق يعيد حساب المعاينة من الأدلة المجمدة ويرفض حذف/تغيير المصدر أو القيد أو التسلسل.
- مطابقة AR/AP تفصل تعديل القيمة الدفترية غير المحقق عن أرصدة الفواتير الأصلية دون إخفاء فرق.
- النسخ الاحتياطي يحفظ العدد والإصدار والمصدر، والاستعادة تعيد ربط المؤسسة وتتحقق مرة أخرى.

## الاختبارات

- TypeScript/Core ناجح.
- 18/18 اختبار C3 مركز قبل اختبار الاستعادة.
- 279/279 وحدة/API كاملة نجحت محلياً.
- 4/4 لاختبارات C3.2 النهائية، وتشمل الاستعادة وإعادة ربط المؤسسة.

CI الكامل هو المرجع النهائي لـEmulator والواجهة والتدقيق الأمني. لا تُعد هذه المرحلة قبول Render لأنها لا تتضمن واجهة مستخدم منشورة بعد.
